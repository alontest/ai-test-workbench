# Interaction Design — Design

## 设计决策

### 决策 1：Dark-first 的工程师工作台风格（暗色为近黑中性）
- **选择**：深色为主、浅色完整可用的开发者工具风格；暗色改为近黑中性（背景 `#0A0A0B`、卡片 `#141416`、弱化表面 `#1C1C1F`、边框 `#2A2A2E`、正文 `#EDEDED`、次要文字 `#A1A1AA`）打底，绿色 `#22C55E` 只承担「运行/成功/焦点」强调，等宽字体承担 ID、模型名、日志与制品预览。
- **理由**：工作台面向测试工程师的长时间桌面使用场景，信息密度高、需要长时间阅读日志与调用记录；`ui-ux-pro-max` 检索命中的风格为 Dark Mode (OLED) + IBM Plex Sans / JetBrains Mono。用户复核时明确不满意初版 slate 色调，要求近黑中性（依据 answers.md：「全部 A，但是你现在的暗色色调我不满意」「暗色基调：近黑中性…强调色保持绿色 #22C55E」），故按新基调重推 Dark token。
- **备选方案**：浅色 SaaS 仪表盘（更亲和，但长时间看日志与时间线对比度不占优）；高饱和品牌色（辨识度高，但与「工具」定位不符）；保留 slate 深蓝（初版，被用户否决）。
- **权衡**：必须同时维护两套颜色 token（AC-UX-2）。近黑底下原深色主按钮 `#1E293B` 失去轮廓，改为反色中性主按钮 `#EDEDED` + `#0A0A0B` 文字，hover `#D4D4D8`；焦点环改用强调绿 `#22C55E`，避免与主按钮同色；阴影在近黑底上作用有限，补 Dark 阴影值并用边框 + 表面色分层。
- **检索说明**：`ui-ux-pro-max --design-system` 返回的 Pattern 为「FAQ/Documentation Landing」，与工作台不匹配，未采用其版式；仅采用其 Style / Colors / Typography / Key Effects。技术栈尚未确定（属于 tech-arch），本次跳过 `--stack` 查询。

### 决策 2：左侧边栏 + 顶栏 + 内容区的三区布局
- **选择**：固定左栏做信息架构，顶栏承载页面标题、当前 UI 状态切换（仅 demo）与主题开关，内容区承担单页任务。侧边栏分三组：工作台（首页 / 会话）、六个入口、基座管理（项目上下文 / AI 提供商与模型 / 调用记录）。
- **理由**：本 spec 有 11 个 US、9 个页面，超过「US ≤ 5 用 Tab」的阈值；入口与基座管理职责不同，分组避免把「配置」混进「开始干活」的路径。
- **备选方案**：顶部 Tab（页面过多会溢出）；纯首页卡片导航（配置类页面难以到达）。
- **权衡**：≤768px 时侧边栏收起为抽屉，多一次点击，但保证小屏可用。

### 决策 3：会话详情是唯一的工作区，右侧输入/调用面板是基座验证面板
- **选择**：会话详情左侧为时间线（输入事件、调用记录、制品事件按发生顺序），右侧为三个 Tab：文本粘贴、文件上传、发起调用；发起调用面板支持提示、上下文勾选与本次参数覆盖。页面顶部提供「标记完成」与「删除会话」。
- **理由**：US-005 的调用由后续业务域通过 `ai.complete` 触发，但 `workbench-core` 需要能让用户验证链路并看到调用记录；US-006 的「可在后续调用中被引用」也要求会话内有可发起调用的位置。把调用面板定位为「基座调试/验证面板」，后续域接入后可替换为业务专用面板。
- **备选方案**：完全不在 UI 暴露调用（只能靠接口验证，用户无法在界面上产生调用记录，P1 调用记录页无数据来源）。
- **权衡**：存在「基座面板」与未来业务面板重复的风险；UXAMB-002 已由用户确认采用建议 A（见本文末「交互歧义假设（UXAMB）」）。

### 决策 4：入口占位由配置驱动，占位页不提供任何输入
- **选择**：每个入口有交付状态（`planned` / `live`）；`planned` 时渲染统一占位页（入口名、所属域、状态、用途、返回首页），不渲染表单、不创建会话；`live` 时渲染真实功能页。本期 6 个入口均为 `planned`。
- **理由**：AC-002-1/2/3 要求占位说明且不产生副作用，并要求占位状态由入口配置决定而非散落硬编码。
- **备选方案**：直接隐藏未交付入口（违反 AC-001-1「6 个入口全部可见」）。
- **权衡**：首页 6 个入口本期都通向占位页，用户的第一落点需要靠侧边栏的「基座管理」承接实际工作。

### 决策 5：登录是唯一入口，未认证访问统一拦截（2026-11-17 返工新增）
- **选择**：新增 `/login` 页面，作为唯一无需认证的页面；`AuthGate` 在路由层拦截未认证的页面访问，跳转登录页并在内存中保留原目标（页面 + 关键参数），登录成功后跳回；受保护接口统一返回 401，前端全局拦截 401 后静默转登录页并提示「会话已过期，请重新登录」。登录页不提供注册、找回口令、多账号或「记住我」。
- **理由**：US-011 / AC-011-1、AC-011-5、AC-011-6、AC-011-7 要求任意页面与接口在未认证时都不得泄露业务数据；初始口令来自部署环境变量 `AW_ADMIN_PASSWORD`，缺失时服务拒绝启动（AC-REQ-17），因此登录页不存在「找回」或「注册」路径；8 小时空闲超时且每次请求刷新、无绝对上限（AC-011-5），「记住我」会与这一会话策略冲突并延长凭据暴露窗口，故不提供。
- **备选方案**：只保护敏感页面（违反 AC-011-1「任意页面」）；把登录做成应用内的普通页面（未登录仍会渲染侧边栏与页面框架，泄露信息架构）；用浏览器 Basic Auth（无法实现统一的锁定倒计时与提示）。
- **权衡**：登录页独立于 AppShell，第一屏信息量小，且未认证时不渲染任何业务 DOM、侧边栏与导航；代价是深链接（如 `/sessions/:id`）依赖前端保留目标参数，刷新页面时由服务端重定向并带回 `next` 参数。
- **范围边界**：登录事件的审计（时间、来源 IP、成功/失败）不在本次需求内，是否入库由 tech-arch 决定（见「待 tech-arch / tech-design 决定」）。

## 核心设计原则

用户确认的 `workbench-core` 六条核心原则。每条给出本项目内的落地解释、对应需求编号与界面区域；线框图与 `docs/demo.html` 已按下列口径自检（见本节末尾「一致性自检」）。

### 原则 1：入口清晰
- **落地**：登录页是唯一入口，未认证访问任何页面都先落到登录页，登录成功后回到原目标；登录后 6 个入口常驻首页与侧边栏，每张卡片同时给出入口名、一句用途、所属域与交付状态；`planned` 入口进入统一占位页并明确「不会创建会话、不会调用模型」；基座管理（项目 / 提供商与模型 / 调用记录）独立成组，不与业务入口混排。
- **对应**：US-001、US-002、US-011、AC-001-1、AC-001-2、AC-002-1、AC-002-3、AC-011-1；界面：登录页、首页入口网格、侧边栏、入口占位页。

### 原则 2：输入明确
- **落地**：每个输入先声明类型、必填性与边界，再给字段级校验与示例：文本（标题可选、正文必填、200,000 字符计数与超限拦截）、文件（类型白名单、单文件 10MB、单次 10 个、同名改名、前 20 行预览）、调用（提示必填、200,000 字符实时计数与超限拦截、上下文只列时间线中真实存在的输入事件与制品、参数覆盖默认取模型登记值）、配置表单（名称 / baseURL / 密钥 / 温度 / max_tokens）。不使用假占位或静默默认值。
- **对应**：US-003、US-004、US-006、US-007、US-008、AC-003-2、AC-004-1、AC-006-2、AC-006-3、AC-007-2、AC-007-3、AC-UX-5；界面：会话输入面板、调用面板、提供商与模型表单、项目表单。

### 原则 3：流程固定
- **落地**：统一路径为「登录 → 项目 → 会话（项目 + 启用模型）→ 输入（文本 / 文件）→ 发起调用 → 记录与状态流转」。未登录不能旁路任何页面：页面跳转登录页、接口返回 401，登录后才能进入业务路径。创建会话前必须有项目与启用模型；调用只能在会话内发起；输入与调用面板同屏但顺序固定（调用面板只能引用已产生的输入事件 / 制品）；会话「已完成 / 失败」后只读，不提供旁路入口。
- **对应**：US-005、US-006、US-007、US-009、US-011、AC-005-3、AC-009-1、AC-009-4、AC-011-1、AC-UX-11；界面：登录页、新建会话对话框、会话详情、状态徽标。
- **边界**：提示文本本身属于输入，因此允许在时间线为空时仅凭提示发起调用，但面板会明确提示「没有可引用的输入」；不把「先有输入事件」做成硬性阻断，避免超出 AC 与 US-005 的基座验证语义。

### 原则 4：输出统一
- **落地**：所有调用结果使用同一「调用结果块」：模型、耗时、重试次数、状态、提示摘要、结果文本；失败块在同结构上追加错误信息。所有制品使用同一卡片：文件名、大小、前 20 行预览、下载、改名提示。调用记录页沿用同一字段顺序（时间、会话、模型、状态、耗时、重试、提示摘要）。不按入口或业务域定制展示格式。
- **对应**：US-005、US-007、US-010、AC-005-1、AC-005-2、AC-005-4、AC-007-1、AC-010-1、AC-010-2；界面：会话时间线、制品卡片、调用记录页。

### 原则 5：风险可控
- **落地**：登录失败只给统一提示「口令错误」，不区分「口令错误」与「凭据不存在」，不泄露口令或哈希；同一来源连续失败 5 次锁定 5 分钟并显示剩余时间，成功登录清零；登录会话空闲 8 小时后失效，重新登录即可继续；显式登出立即回登录页。删除会话、停用提供商、标记完成均二次确认并说明后果（删除列明级联范围、无撤销）；密钥只显示掩码、编辑留空不改；文本超限拒绝而非截断；失败调用必留 AiCallRecord 且不自动切模型；网络错误 / 5xx 至多重试 1 次；会话结束后输入与调用只读。
- **对应**：US-003、US-005、US-006、US-009、US-010、US-011、AC-003-1、AC-005-2、AC-005-5、AC-006-3、AC-009-4、AC-009-5、AC-011-3、AC-011-4、AC-011-5、AC-UX-10、AC-UX-12；界面：登录页、确认对话框、密钥字段、错误态、只读态。

### 原则 6：人工可复核
- **落地**：会话内的每一步产物都能被人检查与复核——输入事件可在时间线展开全文；制品卡片可看预览、下载原始文件；调用记录可展开核对调用编号、模型、状态、耗时、重试次数、提示摘要与错误信息；状态变更作为独立时间线事件记录（已完成 / 失败及操作方式）；界面不隐藏实际使用的参数与重试行为。登录侧保留可复核的入口与说明：登录页明确口令来源（部署环境变量）、锁定原因与剩余时间、会话过期原因；登录事件是否进入审计由 tech-arch 决定，界面不虚构审计记录。
- **对应**：US-005、US-006、US-007、US-009、US-010、US-011、AC-005-4、AC-009-3、AC-010-2、AC-011-4、AC-011-5；界面：登录页、会话时间线、制品卡片、调用记录页。

### 待 tech-arch / tech-design 决定（不自行扩大范围）

- 登录事件（时间、来源 IP、成功 / 失败、锁定）是否进入审计存储；界面是否提供登录历史查看。本期需求只要求失败与锁定行为，不要求审计展示。
- 登录会话令牌的存储与刷新细节（服务端只保存令牌哈希、lastSeenAt 刷新时机、Cookie 属性），以及 401 与页面重定向的服务端实现方式。
- AiCallRecord 是否持久化完整请求 / 响应正文，以及体积、隐私、脱敏与保留策略；界面是否展示全文。
- AI 结果文本的存储形态（AiCallRecord 字段、独立制品或两者兼有）及后续域结构化输出的统一 schema。
- 状态变更审计字段（actor / at / reason）是否入库；单用户自托管下 actor 的取值口径。
- 制品原始内容的预览 / 下载接口与范围（前 N 行、全文、内容类型校验）。
- 调用记录页是否需要跨会话导出或只读分享能力（复核场景）。

入口命名变更（2026-11-17）：原「生成测试用例」更名为「用例库」，生成能力作为该入口内部功能（用例列表 / 详情 / 生成按钮），不再作为独立入口名；路由同步为 `/entrances/case-library`，其余五个入口名称不变。依据：answers.md：「原型还需要补充一下 生成测试用例 其实可以直接叫用例库（生成功能在里边）」。

除 `/login` 外，上表所有路由都受 `AuthGate` 保护：未认证访问时页面重定向到 `/login?next=<原路径>`，接口返回 401；登录成功后回跳 `next`。`next` 只接受站内路径，拒绝绝对 URL 与协议相对地址，避免开放重定向。

- locked：连续失败 5 次后显示锁定与剩余时间，输入框与按钮禁用；倒计时结束自动恢复
- expired：空闲 8 小时后下一次请求返回 401，静默跳登录页并提示「会话已过期，请重新登录。已填写但未提交的内容已保留，重新登录后会恢复。」
- logged-out：显式登出后回到登录页，提示「已退出登录。」

**Key Elements**:
| Element | Type | Behavior |

| 标记完成 | Secondary button | 仅「进行中」可见；二次确认后置为已完成，时间线写入「状态变更 · 已完成」事件并转只读；「失败」只由系统未捕获异常置位，用户不可手动标记失败，已完成/失败不提供重开（UXAMB-005 A） |

**States**:
- default：时间线 + 可用的输入/调用面板
- loading：时间线骨架；调用中 / 上传中显示进行中状态
- success：新事件插入时间线 + toast；调用成功条目含模型、耗时、重试次数、提示摘要
- error：正文空白/超限、提示超限、上传不合规、调用失败（鉴权失败 / 限流 / 超时 / 5xx，含重试次数）均在就近位置展示，消息不含密钥

### 通用状态约定
- **加载**：首屏用骨架屏（不转圈覆盖整页）；按钮内联 loading 并禁用重复提交；超过 400ms 才显示 loading，避免闪烁。
- **成功**：toast 2.4s 自动消失；会话创建、标记完成等有页面级结果的操作额外刷新状态徽标。
- **错误**：就近展示 + 保留用户已填内容；错误文案说明原因与下一步；不可重试的错误（如入口不存在）提供返回路径。
- **空态**：每个列表/时间线都有空态，至少含一句说明；可操作的场景附主 CTA。
- **破坏性操作**：删除会话必须二次确认，列出级联删除范围，按钮文案为动词「删除」；无撤销。
- **只读**：已完成/失败会话的输入面板与调用按钮禁用，展示「会话已结束，不再接受新输入」。
- **密钥**：任何界面只展示掩码；提示摘要与错误信息中不出现密钥原文（交付时以 UI 文案与数据脱敏两层保证）。

### 登录、会话过期与登出（US-011）

- **唯一入口**：`/login` 是唯一无需认证的页面。未认证访问任何页面 → 302 到 `/login?next=<原路径>`；原路径只接受站内路径（以 `/` 开头且不以 `//` 开头），拒绝绝对 URL，防止开放重定向。受保护接口返回 401 且不含业务数据。
- **登录成功**：进入 `next` 指向的原页面；没有 `next` 时进入首页。页面顶部用成功 banner「已登录」提示一次，不弹 toast 干扰。
- **口令输入**：字段始终 `type=password`，不提供「显示口令」切换（避免肩窥；浏览器口令管理器可自动填充）；回车与点击「登录」等效；提交中显示「登录中…」并禁用按钮；失败后保留输入并重新聚焦，便于重试。
- **错误提示**：只显示「口令错误，请重试。」，不区分口令错误与凭据不存在，不显示剩余尝试次数；失败响应与日志均不含口令原文。
- **锁定**：同一来源 IP 连续失败 5 次 → 锁定该来源 5 分钟，显示剩余 `mm:ss` 并每秒刷新；锁定期间口令输入与登录按钮禁用；倒计时结束自动恢复；成功登录后失败计数清零；锁定只影响新的登录尝试，不影响已建立的登录会话。
- **会话过期**：任一请求返回 401（空闲超过 8 小时，每次请求刷新 lastSeenAt、无绝对上限）→ 前端全局拦截，静默跳登录页并提示「会话已过期，请重新登录。已填写但未提交的内容已保留，重新登录后会恢复。」不在页面上覆盖 401 错误块，避免业务数据残留。
- **未提交内容的处理（明确约定）**：过期时把当前页面、目标参数与表单草稿（文本标题 / 正文、调用提示、提供商 / 模型 / 项目 / 新建会话表单）快照到内存；重新登录成功后回到原页面并恢复草稿，页面顶部提示「已恢复上次填写但未提交的内容」。草稿只存在内存，不写 localStorage / sessionStorage / Cookie；**若用户在登录页刷新或关闭标签页，草稿丢失**（登录页会保留原目标，但不再恢复草稿）。已提交并落库的会话、事件、制品不受影响。
- **登出**：顶栏右侧「管理员 ▾」菜单提供「退出登录」，点击立即登出，不弹二次确认（单用户、重新登录成本低）；服务端立即吊销当前令牌，浏览器回到登录页并提示「已退出登录。」；显式登出丢弃未提交草稿，与「会话过期保留草稿」区分。
- **不做项**：不提供注册、找回口令、多账号、角色权限、登录历史页面；不显示 `AW_ADMIN_PASSWORD` 的值或哈希；不提供「记住我」（与 8 小时空闲超时冲突）。登录事件是否入库由 tech-arch 决定，界面不虚构审计记录。
- **可访问性**：登录页只有一个表单，焦点默认落在口令输入；错误 / 锁定 banner 使用 `role="alert"`；颜色之外同时用文字说明原因；倒计时文本可被屏幕阅读器读到但不频繁打断（每秒只更新可读文本，不加 live region 每秒播报）。

### 键盘与可访问性
- Tab 顺序：侧边栏 → 顶栏 → 内容区；对话框打开后焦点进入对话框，Esc 关闭并把焦点还给触发按钮。
- 所有图标按钮有 `aria-label`；状态徽标用文字而非仅颜色区分。
- 焦点环 2px `--color-ring`，不做 `outline: none`。
- 尊重 `prefers-reduced-motion`：关闭过渡与骨架动画。
- 对比度：正文 ≥ 4.5:1，大标题 ≥ 3:1；深色与浅色主题分别校验。

### 响应式
- ≥1024px：侧边栏常驻，会话详情左右两栏（时间线 1fr / 面板 380px）。
- 768–1023px：侧边栏收窄为图标 + 文本；会话详情两栏变上下堆叠。
- <768px：侧边栏为抽屉（顶栏汉堡按钮）；表格改为卡片列表；按钮最小 44×44px。

### 登录相关设计决策（2026-11-17 返工，无需用户拍板，按需求默认值落地）

| # | 取舍 | 决定 | 理由 |
|---|------|------|------|
| 1 | 是否提供「记住我」 | 不提供 | 会话空闲 8 小时、每次请求刷新且无绝对上限（AC-011-5）；「记住我」会延长浏览器侧凭据暴露窗口，与单用户口令的风险控制目标冲突。浏览器口令管理器仍可自动填充。 |
| 2 | 是否提供「显示口令」切换 | 不提供 | 口令始终掩码，避免肩窥；部署者可用口令管理器；错误提示不泄露任何口令信息。 |
| 3 | 登出是否需要确认 | 不需要 | 单用户、重新登录成本低；登出后服务端立即吊销令牌（AC-011-6），不存在数据破坏风险。显式登出丢弃未提交草稿，与「会话过期保留草稿」区分。 |
| 4 | 会话过期时未提交内容 | 内存快照，重新登录后恢复；刷新或关闭标签页则丢失 | 不把业务内容写入 localStorage / Cookie（风险可控）；同一次页面生命周期内尽量不打断用户；实现上由前端全局 401 拦截器持有快照。 |
| 5 | 锁定提示是否显示剩余尝试次数 | 不显示 | 需求只要求「统一提示 + 锁定 5 分钟」；显示剩余次数会暴露阈值，且对单用户没有额外帮助。锁定后显示剩余时间，便于用户判断何时重试。 |
| 6 | 登录页是否复用 AppShell | 不复用 | 未认证时不渲染侧边栏、导航与任何业务 DOM，避免泄露信息架构；登录页只保留品牌、口令表单与主题开关。 |
| 7 | 登录页主题 | 保留 Light / Dark 切换 | 暗色近黑中性为默认，浅色主题完整可用；登录页与工作台共用同一套 token，登录后主题保持一致。 |
