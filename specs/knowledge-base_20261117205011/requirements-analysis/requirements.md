## 功能规格

### 问题陈述

分析会话中，模型对被测项目真实业务定义（术语、实体、规则、流程）缺乏稳定依据，测试工程师只能临时复述业务概念，既费时又容易失真。项目侧已有本地本体工具（`ontology-builder-native` + `ontology-consumption`）产出按编号组织的 `index.json` 与 `.md` 知识，但工作台无法导入、浏览，也无法在调用时按编号引用。

### 目标

- 打通最小闭环「导入 → 浏览 → 注入」，让每次调用的业务依据可追溯、可复现。
- 知识库作为项目级只读资产：用户上传、工作台只读消费、同名重导生成新版本、旧版本只读。
- 注入与用户提示共用 200,000 字符全局上限，超限拒绝而非静默截断。
- 新鲜度与版本冲突只提示、不阻断，且不引入仓库克隆与代码解析。

### 非目标

见「功能范围 / Out of Scope」。

### 需求清单（FR）

- **FR-01 导入校验**：仅接受 `.json` / `.md` / `.markdown`，必须含 `index.json`；`index.json` ≤20MB、其他单文件 ≤10MB、单次 ≤50 个、单库合计 ≤100MB；不合规逐项拒绝且不写入任何文件、不创建知识库。
- **FR-02 索引建立**：`index.json` 须为合法 JSON 且含版本标识与非空条目集合；按编号建索引，前缀 `TERM/ENT/ST/BR/BP/API/DE` 映射七类，未知前缀归「其他」。
- **FR-03 部分失败与回滚**：条目级不合法（缺编号、编号重复、字段类型错误）跳过并在报告列行号与原因；无可导入条目或中途出错则整体失败并回滚全部落盘结果。
- **FR-04 浏览与检索**：支持按项目、知识库、类型筛选与编号前缀 / 完整编号 / 关键词检索；详情含结构化字段、一跳邻居、来源文件与新鲜度；正文缺失时展示摘要并标注。
- **FR-05 版本链**：知识库归属项目（0..n），同项目名称唯一；同名重新导入生成新版本，旧版本只读，浏览默认最新版，被取代版本提供跳转。
- **FR-06 注入**：按「编号 + 标题 + 正文（缺失用摘要）」拼装；注入正文与提示正文合计 ≤200,000 字符；超限拒绝并显示分段字数与上限，不截断。
- **FR-07 留痕与脱敏**：AiCallRecord 与 SessionEvent 记录知识库、版本、编号列表与字符数，不复制正文；知识库正文与注入内容不进入应用日志与错误响应。
- **FR-08 删除语义**：删除级联知识库、条目与文件并移除项目关联；历史会话、制品与调用记录不变，相关编号标「知识库已删除」。

### 成功指标

- 5 个用户故事的 24 条 AC 与 7 条 EARS 验收标准全部通过（测试报告逐条对应）。
- 每次使用注入的调用 100% 可在调用记录与会话事件中回查到知识库名、版本、编号列表与字符数（AC-014-2、AC-014-5）。
- 导入失败场景 0 残留：不出现「有文件无记录」或「有记录无文件」（AC-012-7）。
- 超限场景 0 截断：超 200,000 字符时调用不发起、条目不被丢弃或截断（AC-014-3）。
- 脱敏场景 0 泄露：日志与错误响应中不出现条目正文、摘要与字段值（BR-C18）。

## 用户故事

### US-012：导入知识库并建立编号索引

**As a** 测试工程师
**I want to** 把本地生成的知识库文件上传到某个项目
**So that** 后续分析能按稳定编号引用项目已有的术语、实体、规则与流程

**Priority**: P0 | **Related goal**: BG-05

**Acceptance Criteria**:
- AC-012-1: GIVEN 我在某项目下发起知识库导入 WHEN 我上传包含一个 `index.json` 与可选 `.md` / `.markdown` 的文件 THEN 系统完成校验与解析后创建知识库，列表展示名称、生成时间（缺失显示「未知」）、条目数与状态「已就绪」
- AC-012-2: GIVEN 上传文件的类型不在 `.json .md .markdown`、缺少 `index.json`、单文件或单次导入超过 AMB-014 约定的上限 WHEN 我提交 THEN 系统拒绝导入并逐项说明允许范围与上限，不写入任何文件、不创建知识库
- AC-012-3: GIVEN `index.json` 不是合法 JSON、缺少最小结构（版本标识 + 条目集合）或条目集合为空 WHEN 我提交 THEN 系统拒绝导入并提示期望的最小结构，不创建知识库
- AC-012-4: GIVEN `index.json` 合法 WHEN 系统解析 THEN 每个条目按编号建立索引，记录编号、类型、标题、字段、表、代码路径、一跳邻居与新鲜度；`TERM-` / `ENT-` / `ST-` / `BR-` / `BP-` / `API-` / `DE-` 分别映射为术语 / 实体 / 状态 / 业务规则 / 流程 / 接口 / 领域事件，未知前缀保留编号并归入「其他」
- AC-012-5: GIVEN 解析过程中部分条目不合法（缺编号、编号重复或字段类型错误） WHEN 解析结束 THEN 系统跳过该条目并在导入报告中列出行号与原因，其余条目正常导入；若没有任何可导入条目则整体失败
- AC-012-6: GIVEN 知识库导入成功 WHEN 我打开项目上下文页 THEN 看到该项目关联的 0..n 个知识库及其状态，并可跳转到该知识库的浏览页
- AC-012-7: GIVEN 导入失败或在解析、落盘途中出错 WHEN 系统结束导入 THEN 不留下任何已落盘文件、知识库记录或条目索引（整体回滚）

### US-013：浏览与检索知识库条目

**As a** 测试工程师
**I want to** 按编号、类型或关键词查看知识库条目
**So that** 我能在发起调用前确认这条业务概念到底说了什么、落在代码哪里

**Priority**: P0 | **Related goal**: BG-05

**Acceptance Criteria**:
- AC-013-1: GIVEN 项目下已有知识库 WHEN 我打开知识库浏览页 THEN 页面按知识库与类型分组列出条目编号与标题，并支持按项目、知识库与类型筛选；无匹配时展示空态而不是错误
- AC-013-2: GIVEN 我在浏览页 WHEN 我点击某个编号 THEN 详情页展示该条目的字段、表、代码路径、一跳邻居、来源文件与新鲜度信息；邻居编号可点击跳转到同项目内对应条目
- AC-013-3: GIVEN 我在检索框 WHEN 我输入编号前缀、完整编号或关键词（匹配标题、摘要与正文） THEN 结果只返回匹配条目，并标明所属知识库与版本；无匹配时展示空态
- AC-013-4: GIVEN 某条目所在版本已被同项目的新版本取代 WHEN 我查看详情 THEN 页面标注「已被新版本取代」并提供跳转到最新版本的入口；浏览页默认展示最新版本
- AC-013-5: GIVEN 条目正文来自 `.md` 文件 WHEN 我查看详情 THEN 展示该正文；若对应 `.md` 未上传或无法匹配 THEN 展示 `index.json` 中的摘要并标注「正文缺失」，不以空内容冒充正文

### US-014：勾选编号注入调用上下文

**As a** 测试工程师
**I want to** 在会话里勾选若干知识库编号并把它们注入本次调用
**So that** 模型回答基于项目真实的业务定义，而不是我临时复述的理解

**Priority**: P0 | **Related goal**: BG-05

**Acceptance Criteria**:
- AC-014-1: GIVEN 我在会话内 WHEN 我打开知识库选择器并按编号勾选条目 THEN 选择器实时显示已选条目数、知识库注入字符数与「用户正文 + 注入」的合计字符数
- AC-014-2: GIVEN 我勾选了条目并发起调用 WHEN 调用发起 THEN 系统在提示上下文中按「编号 + 标题 + 正文（缺失时用摘要）」注入所选条目，并在该次 AiCallRecord 与 SessionEvent 中记录知识库、编号列表与字符数（不记录正文）
- AC-014-3: GIVEN 用户提示正文与勾选条目正文合计超过 200,000 字符 WHEN 我发起调用 THEN 系统拒绝发起调用并显示提示正文字符数、注入字符数、合计与 200,000 上限，不静默截断；取消勾选或缩短正文后可重试
- AC-014-4: GIVEN 勾选的条目属于已删除知识库、已被新版本取代或已不存在 WHEN 我发起调用 THEN 系统在发起外部请求前剔除这些条目并弹出阻塞式确认，列出被剔除的具体编号（不静默降级）；我确认后其余有效条目照常参与本次调用并产生 AiCallRecord，我取消则不发起调用且不产生 AiCallRecord（2026-11-18 按 AMB-026 修正，原条文见「需求澄清」修正记录）
- AC-014-5: GIVEN 我已注入条目并完成调用 WHEN 我回看会话与调用记录 THEN 能看到所用知识库、编号列表与字符数；知识库正文与注入内容不出现在应用日志与错误响应中

### US-015：识别知识库新鲜度与版本冲突

**As a** 测试工程师
**I want to** 在浏览与注入时看到知识库是否过期或存在版本冲突
**So that** 我不会把过期定义当成当前事实

**Priority**: P1 | **Related goal**: BG-05

**Acceptance Criteria**:

### US-016：删除知识库

**As a** 测试工程师
**I want to** 删除不再需要的知识库
**So that** 项目里只保留当前有效的业务知识

**Priority**: P1 | **Related goal**: BG-05

**Acceptance Criteria**:
- AC-016-1: GIVEN 项目下存在知识库 WHEN 我确认删除 THEN 知识库、其条目索引与已存文件一并删除，项目关联同步移除，浏览页不再出现
- AC-016-2: GIVEN 知识库已删除 WHEN 我回看引用过它的历史会话与调用记录 THEN 记录与编号列表保留，并标注「知识库已删除」；历史会话的事件、制品与调用记录不被修改或清空

## 验收标准（EARS 格式）

### AC-REQ-18
WHEN 用户向项目导入知识库文件 THEN 系统 SHALL 仅接受 `.json` 与 `.md` / `.markdown`、要求包含合法 `index.json`，并按 AMB-014 约定的类型、单文件大小、文件数量与总大小上限校验；不合规时 SHALL 拒绝导入并说明允许范围，SHALL NOT 写入文件或创建知识库。

### AC-REQ-19
WHEN `index.json` 通过校验 THEN 系统 SHALL 按编号建立条目索引（编号、类型、标题、字段、表、代码路径、一跳邻居、新鲜度），未知编号前缀 SHALL 保留并归入「其他」；部分条目非法时 SHALL 跳过并在导入报告中说明行号与原因；没有任何可导入条目时 SHALL 整体失败并回滚全部落盘结果。

### AC-REQ-20
WHEN 用户浏览知识库 THEN 系统 SHALL 支持按项目、知识库、类型筛选以及按编号前缀、完整编号或关键词检索，并展示条目详情与新鲜度；无匹配时 SHALL 展示空态；条目正文缺失时 SHALL 展示摘要并标注「正文缺失」。

### AC-REQ-21
WHEN 用户在会话中勾选知识库条目并调用 `ai.complete` THEN 系统 SHALL 按「编号 + 标题 + 正文（缺失用摘要）」注入，并在 AiCallRecord 与 SessionEvent 记录知识库、编号列表与字符数；注入正文与用户提示正文合计超过 200,000 字符时 SHALL 拒绝调用并显示分段字符数与上限，SHALL NOT 截断或静默丢弃条目。

### AC-REQ-22
WHEN 知识库条目存在新鲜度信息或同编号内容冲突 THEN 系统 SHALL 展示生成时间、条目新鲜度、「可能过期」或「版本冲突」提示，并在注入块中携带知识库名与生成时间；这些提示 SHALL NOT 单独阻止调用，系统 SHALL NOT 克隆仓库或解析代码校验新鲜度。

### AC-REQ-23
WHEN 用户删除知识库 THEN 系统 SHALL 级联删除其条目索引与已存文件并移除项目关联，SHALL NOT 修改历史会话、制品与 AiCallRecord；历史记录中相关编号 SHALL 标注「知识库已删除」。

### AC-REQ-24
WHEN 用户查看项目上下文 THEN 系统 SHALL 展示该项目关联的 0..n 个知识库；同一项目下知识库名 SHALL 唯一，同名重新导入 SHALL 按 AMB-017 约定生成新版本并保留旧版本只读。
