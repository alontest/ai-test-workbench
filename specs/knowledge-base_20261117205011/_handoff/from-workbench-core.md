## 3. 用户故事与 AC 原文

### US-012：导入知识库并建立编号索引

**As a** 测试工程师
**I want to** 把本地生成的知识库文件上传到某个项目
**So that** 后续分析能按稳定编号引用项目已有的术语、实体、规则与流程

**Priority**: P0 | **Related goal**: BG-05

**Acceptance Criteria**:
- **AC-012-1**: GIVEN 我在某项目下发起知识库导入 WHEN 我上传包含一个 `index.json` 与可选 `.md` / `.markdown` 的文件 THEN 系统完成校验与解析后创建知识库，列表展示名称、生成时间（缺失显示「未知」）、条目数与状态「已就绪」
- **AC-012-2**: GIVEN 上传文件的类型不在 `.json .md .markdown`、缺少 `index.json`、单文件或单次导入超过 AMB-014 约定的上限 WHEN 我提交 THEN 系统拒绝导入并逐项说明允许范围与上限，不写入任何文件、不创建知识库
- **AC-012-3**: GIVEN `index.json` 不是合法 JSON、缺少最小结构（版本标识 + 条目集合）或条目集合为空 WHEN 我提交 THEN 系统拒绝导入并提示期望的最小结构，不创建知识库
- **AC-012-4**: GIVEN `index.json` 合法 WHEN 系统解析 THEN 每个条目按编号建立索引，记录编号、类型、标题、字段、表、代码路径、一跳邻居与新鲜度；`TERM-` / `ENT-` / `ST-` / `BR-` / `BP-` / `API-` / `DE-` 分别映射为术语 / 实体 / 状态 / 业务规则 / 流程 / 接口 / 领域事件，未知前缀保留编号并归入「其他」
- **AC-012-5**: GIVEN 解析过程中部分条目不合法（缺编号、编号重复或字段类型错误） WHEN 解析结束 THEN 系统跳过该条目并在导入报告中列出行号与原因，其余条目正常导入；若没有任何可导入条目则整体失败
- **AC-012-6**: GIVEN 知识库导入成功 WHEN 我打开项目上下文页 THEN 看到该项目关联的 0..n 个知识库及其状态，并可跳转到该知识库的浏览页
- **AC-012-7**: GIVEN 导入失败或在解析、落盘途中出错 WHEN 系统结束导入 THEN 不留下任何已落盘文件、知识库记录或条目索引（整体回滚）

**As a** 测试工程师
**I want to** 按编号、类型或关键词查看知识库条目
**So that** 我能在发起调用前确认这条业务概念到底说了什么、落在代码哪里

**Priority**: P0 | **Related goal**: BG-05

**Acceptance Criteria**:
- **AC-013-1**: GIVEN 项目下已有知识库 WHEN 我打开知识库浏览页 THEN 页面按知识库与类型分组列出条目编号与标题，并支持按项目、知识库与类型筛选；无匹配时展示空态而不是错误
- **AC-013-2**: GIVEN 我在浏览页 WHEN 我点击某个编号 THEN 详情页展示该条目的字段、表、代码路径、一跳邻居、来源文件与新鲜度信息；邻居编号可点击跳转到同项目内对应条目
- **AC-013-3**: GIVEN 我在检索框 WHEN 我输入编号前缀、完整编号或关键词（匹配标题、摘要与正文） THEN 结果只返回匹配条目，并标明所属知识库与版本；无匹配时展示空态
- **AC-013-4**: GIVEN 某条目所在版本已被同项目的新版本取代 WHEN 我查看详情 THEN 页面标注「已被新版本取代」并提供跳转到最新版本的入口；浏览页默认展示最新版本
- **AC-013-5**: GIVEN 条目正文来自 `.md` 文件 WHEN 我查看详情 THEN 展示该正文；若对应 `.md` 未上传或无法匹配 THEN 展示 `index.json` 中的摘要并标注「正文缺失」，不以空内容冒充正文

**As a** 测试工程师
**I want to** 在会话里勾选若干知识库编号并把它们注入本次调用
**So that** 模型回答基于项目真实的业务定义，而不是我临时复述的理解

**Priority**: P0 | **Related goal**: BG-05

- **AC-014-2**: GIVEN 我勾选了条目并发起调用 WHEN 调用发起 THEN 系统在提示上下文中按「编号 + 标题 + 正文（缺失时用摘要）」注入所选条目，并在该次 AiCallRecord 与 SessionEvent 中记录知识库、编号列表与字符数（不记录正文）
- **AC-014-3**: GIVEN 用户提示正文与勾选条目正文合计超过 200,000 字符 WHEN 我发起调用 THEN 系统拒绝发起调用并显示提示正文字符数、注入字符数、合计与 200,000 上限，不静默截断；取消勾选或缩短正文后可重试
- **AC-014-4**: GIVEN 勾选的条目属于已删除知识库、已被新版本取代或已不存在 WHEN 我发起调用 THEN 系统在发起外部请求前提示具体条目并阻止使用，其余有效条目不受影响，且不产生 AiCallRecord
- **AC-014-5**: GIVEN 我已注入条目并完成调用 WHEN 我回看会话与调用记录 THEN 能看到所用知识库、编号列表与字符数；知识库正文与注入内容不出现在应用日志与错误响应中

### US-015：识别知识库新鲜度与版本冲突

**As a** 测试工程师
**I want to** 在浏览与注入时看到知识库是否过期或存在版本冲突
**So that** 我不会把过期定义当成当前事实

**Priority**: P1 | **Related goal**: BG-05

**Acceptance Criteria**:
- **AC-015-1**: GIVEN 知识库已导入 WHEN 我查看浏览页或条目详情 THEN 页面展示 `index.json` 提供的生成时间与条目新鲜度；字段缺失时显示「未知」，不推测
- **AC-015-2**: GIVEN 同一项目下两个知识库或同一知识库的两个版本存在相同编号且内容摘要不同 WHEN 我查看该条目 THEN 页面标注「版本冲突」并列出冲突来源（知识库名 + 版本 + 生成时间）
- **AC-015-3**: GIVEN 条目新鲜度时间距当前超过 30 天（AMB-016 已确认） WHEN 我查看或勾选该条目 THEN 标注「可能过期」；注入预览与注入块携带知识库名与生成时间
- **AC-015-4**: GIVEN 新鲜度或冲突提示存在 WHEN 我发起调用 THEN 系统只提示不阻止（条目已删除或已失效时按 AC-014-4 处理）；系统不克隆仓库、不解析代码去校验新鲜度

- **AC-016-2**: GIVEN 知识库已删除 WHEN 我回看引用过它的历史会话与调用记录 THEN 记录与编号列表保留，并标注「知识库已删除」；历史会话的事件、制品与调用记录不被修改或清空

### EARS 验收标准原文（AC-REQ-18 ~ AC-REQ-24）

#### AC-REQ-18
WHEN 用户向项目导入知识库文件 THEN 系统 SHALL 仅接受 `.json` 与 `.md` / `.markdown`、要求包含合法 `index.json`，并按 AMB-014 约定的类型、单文件大小、文件数量与总大小上限校验；不合规时 SHALL 拒绝导入并说明允许范围，SHALL NOT 写入文件或创建知识库。

#### AC-REQ-19
WHEN `index.json` 通过校验 THEN 系统 SHALL 按编号建立条目索引（编号、类型、标题、字段、表、代码路径、一跳邻居、新鲜度），未知编号前缀 SHALL 保留并归入「其他」；部分条目非法时 SHALL 跳过并在导入报告中说明行号与原因；没有任何可导入条目时 SHALL 整体失败并回滚全部落盘结果。

#### AC-REQ-20
WHEN 用户浏览知识库 THEN 系统 SHALL 支持按项目、知识库、类型筛选以及按编号前缀、完整编号或关键词检索，并展示条目详情与新鲜度；无匹配时 SHALL 展示空态；条目正文缺失时 SHALL 展示摘要并标注「正文缺失」。

#### AC-REQ-21
WHEN 用户在会话中勾选知识库条目并调用 `ai.complete` THEN 系统 SHALL 按「编号 + 标题 + 正文（缺失用摘要）」注入，并在 AiCallRecord 与 SessionEvent 记录知识库、编号列表与字符数；注入正文与用户提示正文合计超过 200,000 字符时 SHALL 拒绝调用并显示分段字符数与上限，SHALL NOT 截断或静默丢弃条目。

#### AC-REQ-22
WHEN 知识库条目存在新鲜度信息或同编号内容冲突 THEN 系统 SHALL 展示生成时间、条目新鲜度、「可能过期」或「版本冲突」提示，并在注入块中携带知识库名与生成时间；这些提示 SHALL NOT 单独阻止调用，系统 SHALL NOT 克隆仓库或解析代码校验新鲜度。

#### AC-REQ-23
WHEN 用户删除知识库 THEN 系统 SHALL 级联删除其条目索引与已存文件并移除项目关联，SHALL NOT 修改历史会话、制品与 AiCallRecord；历史记录中相关编号 SHALL 标注「知识库已删除」。

#### AC-REQ-24
WHEN 用户查看项目上下文 THEN 系统 SHALL 展示该项目关联的 0..n 个知识库；同一项目下知识库名 SHALL 唯一，同名重新导入 SHALL 按 AMB-017 约定生成新版本并保留旧版本只读。

## 4. 涉及实体与业务规则原文

### 实体

#### ENT-C10 知识库（KnowledgeBase）
- **对应图谱**：未覆盖
- **定义**：项目级、只读导入的业务知识集合，由 `index.json` 与可选 `.md` 文件构成
- **关键属性**：kbId、projectId、name（同项目内唯一）、version、indexGeneratedAt、entryCount、status（已就绪 / 导入失败 / 已被取代）、totalByteSize、createdAt、updatedAt
- **所属模块**：workbench-core（迁出后应为 knowledge-base）
- **来源 spec**：ai-test-workbench_20261117184149

#### ENT-C11 知识库条目（KnowledgeEntry）
- **对应图谱**：未覆盖
- **定义**：知识库中按编号索引的一条业务知识，是浏览、检索与注入的最小引用单位
- **关键属性**：entryId、kbId、code（编号）、type（术语 / 实体 / 状态 / 业务规则 / 流程 / 接口 / 领域事件 / 其他）、title、summary、body、fields、tables、codePaths、neighbors、freshnessAt、contentDigest
- **所属模块**：workbench-core（迁出后应为 knowledge-base）
- **来源 spec**：ai-test-workbench_20261117184149

#### 会话事件中的注入载荷（原 `docs/context.md`「数据实体」）
- KnowledgeInjection（会话事件载荷）：sessionId、kbId、entryCodes、injectedChars、createdAt；只记录编号与字符数，不复制条目正文

### 业务规则

#### BR-C15 知识库导入边界与回滚

### 术语（原 glossary.md）

- TERM-C10 知识库（KnowledgeBase）：由外部本体工具（`ontology-builder-native` + `ontology-consumption`）产出的、按编号组织的业务知识文件集合（`index.json` + `.md`），由用户上传到某个项目，供浏览与按编号注入；工作台只读，不在线编辑。避免叫法：知识图谱、向量库、文档库。
- TERM-C11 知识库条目（KnowledgeEntry）：知识库中按编号（如 `ENT-123`、`BR-045`）标识的一条业务知识，含类型、标题、字段、表、代码路径、一跳邻居与新鲜度；编号是浏览、检索与注入的稳定引用键。避免叫法：节点、记录、文档片段。
- TERM-C12 知识注入（Knowledge Injection）：会话发起调用时，把用户勾选的若干知识库条目按「编号 + 标题 + 正文（缺失用摘要）」拼入提示上下文；注入正文与用户提示正文合计受 200,000 字符上限约束，注入的知识库与编号记入 AiCallRecord 与 SessionEvent。避免叫法：RAG、检索增强、前置知识。

### 业务流程（原 processes.md）

- BP-C5 知识库导入：触发条件 = 用户在项目下上传知识库文件（`index.json` + 可选 `.md`）；操作对象 = ENT-C10（创建知识库并关联项目）、ENT-C11（按编号建立条目索引）。
- BP-C6 知识库条目浏览与检索：触发条件 = 用户打开知识库浏览页，按项目 / 知识库 / 类型筛选或输入编号、关键词检索；操作对象 = ENT-C11（只读查询条目详情、一跳邻居与新鲜度）。
- BP-C7 知识库条目注入调用：触发条件 = 用户在会话内勾选知识库条目并调用 `ai.complete`；操作对象 = ENT-C11（读取条目正文并拼接注入块）、ENT-C7（记录注入编号与字符数）、ENT-C5（追加注入事件）。
- BP-C8 知识库删除：触发条件 = 用户二次确认删除知识库；操作对象 = ENT-C10、ENT-C11（级联删除条目索引与已存文件，移除项目关联；历史会话不改）。

## 5. 流程图要点（原 docs/flowchart.md 对应 US 的 mermaid）

- **US-012 导入**：发起导入 → 类型仅 `.json` / `.md` 且包含 `index.json`（否则拒绝并说明）→ 单文件/文件数/总量在上限内（否则逐项说明）→ `index.json` 合法且含最小结构（否则提示期望结构）→ 按编号解析并建索引 → 存在不合法条目则跳过并在导入报告列行号与原因 → 仍有可导入条目则创建知识库并关联项目，否则整体失败并回滚已落盘文件 → 浏览页可见。
- **US-013 浏览与检索**：打开浏览页 → 按项目/知识库/类型筛选 → 有检索词时按编号前缀/完整编号/关键词返回匹配并标明知识库与版本，无匹配空态 → 点击编号进详情，展示字段/表/代码路径/一跳邻居/新鲜度 → 版本已被取代则标注并提供跳转 → `.md` 正文存在则展示正文，否则展示摘要并标「正文缺失」。
- **US-014 注入**：会话内打开知识库选择器 → 按编号勾选 → 实时计算注入字符数与合计 → 条目无效（已删除/已失效）则提示并阻止该条目 → 用户正文 + 注入 ≤ 200,000 才允许调用，超限拒绝并显示分段字符数与上限 → 调用 `ai.complete`，按「编号 + 标题 + 正文」注入 → 写 AiCallRecord 与 SessionEvent（知识库、编号列表、字符数）；日志不含正文。
- **US-015 新鲜度与冲突**：查看条目或勾选注入 → `index.json` 无新鲜度字段则显示未知，有则显示生成时间与条目新鲜度 → 同编号摘要冲突标「版本冲突」并列出冲突来源 → 新鲜度超 30 天标「可能过期」→ 注入块携带知识库名与生成时间 → 仅提示不阻止，用户仍可注入或取消勾选。
- **US-016 删除**：选择删除知识库 → 二次确认（取消则结束）→ 删除条目索引与已存文件 → 移除项目关联 → 历史会话、制品与调用记录保持不变 → 相关编号标「知识库已删除」。

## 7. 已核实的接口 / 格式事实

- **无外部网络接口**：知识库不调用任何外部服务，唯一输入是用户上传的文件。
- **上游工具**：`ontology-builder-native`（生成本体）与 `ontology-consumption`（产出一组只读中文参考文档 + `index.json` 机器索引），在工作台之外运行；工作台只读消费其产出（answers.md 2026-11-17 20:06:58）。
- **`index.json` 最小结构（technical-design 已定，2026-11-17 20:27:18 OQ-ARCH-06 全 A）**：顶层对象 + 非空字符串 `schema`（版本标识）+ 非空数组 `entries`；KB 生成时间取 `meta.source.exported_at`，兼容顶层 `generated_at`，缺失为「未知」；上游目前**没有条目级新鲜度字段**，`freshness_at`/`updated_at` 为可选扩展。
- **条目字段与解析规则**：`id`（编号，必填，≤128，`^[\w一-鿿][\w一-鿿.\-]{0,127}$`）、`zh_name`/`name`、`zh_definition`/`description`/`content`、`fields`（对象）、`tables`（字符串数组）、`code_paths`（字符串数组）、`neighbors[{id,relation,relation_name,dir}]`（最多 200）、`source_doc`、`anchor`、`extra`；类型按前缀映射（`TERM→term`、`ENT→entity`、`ST→state`、`BR→rule`、`BP→process`、`API→api`、`DE→domain_event`，其他→`other`），不信任条目自带 type。
- **解析护栏（OQ-ARCH-06 A）**：单库 ≤20,000 条、JSON 深度 ≤32 层、单条一跳邻居 ≤200、`extra` ≤64KB；超限整包拒绝并报实测值。
- **正文匹配**：`.md` 文件名去扩展名等于 `code_key` → 整文件为正文；否则按 `^### (\S+)\s*$` 切块；一份正文命中多个条目取文件名升序 + 偏移最小者；未匹配文件仍保存并记入报告；正文为空 → `body_missing=true`。
- **检索（OQ-ARCH-07 A）**：可移植 `LIKE '%q%'`（转义 `% _ \`），不做 MySQL FULLTEXT / SQLite FTS5；接口与 digest 不变。
- **删除语义（OQ-ARCH-09 A）**：删除知识库 = 删除同项目同名逻辑库的全部版本与文件，名称可重新使用。
- **注入组装**：唯一入口 `KnowledgeInjectionService.prepare/preview`，唯一预算校验点 `AiGateway.complete`；模板「【知识库上下文】→ 每库一行 `知识库：<name> v<version>（生成时间：<ISO8601|未知>）` → 每条形如 `### <code> <title>` + 正文（缺失则摘要 + 「（正文缺失）」）」；字符口径为 Unicode 码点；超限错误 `prompt_budget_exceeded`，返回 `promptChars / injectedChars / totalChars / limit`。
- **限额默认值**：`AW_KB_MAX_INDEX_BYTES=20MB`、`AW_KB_MAX_FILE_BYTES=10MB`、`AW_KB_MAX_FILES=50`、`AW_KB_MAX_TOTAL_BYTES=100MB`、`AW_KB_MAX_ENTRIES=20000`、`AW_KB_MAX_JSON_DEPTH=32`、`AW_KB_MAX_NEIGHBORS=200`、`AW_KB_MAX_EXTRAS_BYTES=64KB`、`AW_KB_STALE_DAYS=30`、`AW_KB_CONFLICT_SOURCES=20`、`AW_PROMPT_MAX_CHARS=200000`。
- **导入流程与原子性**：`.staging/` 流式写入并校验 → 解析 → 取版本号 → `rename` 到 `knowledge-bases/<kbId>` → 单事务写 KB 行与条目 → 提交；任一步失败回滚并删目录；启动时清理「有目录无 DB 行」（mtime > 1 小时）。
- **文件命名**：`sha256(内容)[:16] + "__" + slug(原文件名)`，客户端文件名不拼进路径。

## 8. 仍标「待技术方案」/ 未核实项

- 登录与知识库无关，迁出后知识库仍需决定：多用户/权限（当前继承 core 的单用户登录边界）。
- 检索大数据量下的分页方式与性能退化后的 FTS 升级时机（当前结论：`LIKE` + `limit 50 / 上限 200` + cursor）。
- 知识库与「项目上下文」页的耦合：迁出后 `ProjectContext` 归属仍需与 workbench-core 协商（跨 spec 依赖：知识库引用 projectId，core 拥有 ProjectContext）。
- 注入字符计数的「提示」部分由 core 的 `ai.complete` 唯一校验；迁出后若知识库独立部署，需确定与 core 的进程内接口归属（原结论：`PreparedPrompt` 交给 `AiGateway`）。
- 上游 `index.json` 尚无条目级新鲜度字段，「可能过期」只能在用户提供 `freshness_at`/`updated_at` 时生效（原样保留）。
- 导入报告行号为「尽力而为」（定位 `"id": "<code>"` 首次出现的行，找不到回退 `entries[<index>]`）。
- 来自 interaction-design「待 tech-arch / tech-design 决定」的知识库项：`index.json` 具体字段与向下兼容策略、检索服务端/前端、`.md` 与条目匹配规则、存储布局与删除事务边界、注入块最终拼装格式（后续 technical-design 已给出默认结论，见第 7 节，但仍未实现）。
