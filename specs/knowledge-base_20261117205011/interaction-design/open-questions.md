## OQ-UX-KB-01 注入字符预算的统计口径（UXAMB-001）

- **UXAMB 编号**：UXAMB-001
- **状态**：已确认
- **依据**：answers.md：「其他按建议」（2026-11-18 11:02:41）
- **关联用户故事**：US-014（AC-014-1 / AC-014-3）
- **问题**：界面上的「注入字符数」是只统计条目正文 / 摘要，还是统计最终注入块的全部字符（编号、标题、正文或摘要、知识库名与生成时间）？若 UI 只按正文计，用户看到的合计可能小于 core 对最终 prompt 的校验值，出现「显示未超限但调用被拒」。
- **选项**：
  - A（建议）：按最终注入块全部字符计，与 `AiGateway` 对最终 prompt 的校验同口径；分段展示「注入 X 字符（含编号与标题）· 提示 Y 字符 · 合计 Z / 200,000」。
  - B：只统计正文 / 摘要，包装字符不计；与 AMB-015 字面一致，但需接受 UI 合计与最终校验可能存在的差额，并在超限时以 core 的拒绝为准。
- **建议默认值**：A
- **影响**：`design.md` 线框图与 `demo.html` 的计数、`docs/context.md` 的「字符预算」约定；不改变 200,000 常量归属。

## OQ-UX-KB-02 失效条目阻塞确认取消后的状态（UXAMB-002）

- **UXAMB 编号**：UXAMB-002
- **状态**：已确认
- **依据**：answers.md：「其他按建议」（2026-11-18 11:02:41）
- **关联用户故事**：US-014（AC-014-4 / AC-UX-25）
- **问题**：用户点击「取消」后，已勾选条目、失效条目与提示正文如何处理？是否需要在面板上留存「本次未发起」的说明？
- **选项**：
  - A（建议）：取消 = 不发起调用、不产生 AiCallRecord；对话框关闭；失效条目自动取消勾选并标「不可用」；其余勾选与提示原样保留，面板提示「本次未发起：已取消，N 条失效条目已移除」。
  - B：取消后清空全部勾选，仅保留提示，强制用户重新选择。
- **建议默认值**：A
- **影响**：`KbInvalidEntryDialog` 的取消分支、`KbInjectPicker` 的失效条目状态、demo 的取消用例。

## OQ-UX-KB-03 会话打开期间同名新版本导入时的选择器刷新（UXAMB-003）

- **UXAMB 编号**：UXAMB-003
- **状态**：已确认
- **依据**：answers.md：「其他按建议」（2026-11-18 11:02:41）
- **关联用户故事**：US-014 / US-015
- **问题**：选择器只列「当前项目最新版本条目」；若会话打开期间同名知识库又导入了新版本，已勾选条目会被取代。此时是否自动刷新列表？已勾选条目如何处理？
- **选项**：
  - A（建议）：不自动刷新（避免勾选突然消失）；点击「发起调用」时重新校验，被取代条目走 UXAMB-002 的阻塞确认；选择器顶部显示知识库名与版本，下次进入会话使用新版本。
  - B：检测到新版本即刷新列表并清空已勾选条目，顶部提示「知识库已更新，请重新勾选」。
- **建议默认值**：A
- **影响**：`KbInjectPicker` 的版本显示、失效校验时机、demo 的「模拟新版本导入」用例。
