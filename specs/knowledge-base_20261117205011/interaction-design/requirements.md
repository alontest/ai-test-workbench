# Interaction Design — Requirements

## 交付范围

### 必须交付

| 交付物 | 验收标准 |
|--------|---------|
| 页面线框图 | US-012 ~ US-016 各对应至少一个页面线框图，含布局示意、关键元素表与 default / loading / success / error / empty 状态；另含失效条目阻塞确认、删除确认两个模态线框 |
| 用户流程图 | US-012 ~ US-016 各一张 Mermaid 流程图，含开始 / 结束节点与带标签的决策分支 |
| Design Tokens | 沿用 workbench-core 的 Light / Dark 两套 token，覆盖颜色 / 字体 / 间距 / 圆角 / 阴影五类；本 spec 不新增 token |
| 组件清单 | 知识库自有组件列出用途、关键输入与状态列表；状态名与业务口径一致 |
| 交互约定 | 导入校验文案、字符预算、失效条目阻塞确认、删除确认、空 / 加载 / 错误态、键盘与无障碍约定 |
| demo.html | 单文件、离线可用，覆盖 5 个 US 的页面、五种 UI 状态、阻塞确认与删除确认、Light / Dark 主题 |
| 入口与壳 | 复用 core 的 AppShell、`AuthGate` 与设计 token；侧边栏「基座管理」新增「知识库」入口，会话调用面板内嵌注入选择器；不改造 core 页面布局 |

### Out of Scope

- 技术实现细节（框架、状态管理、接口签名）：属于 technical-design 职责
- 后端 API、存储布局、检索实现与注入拼装的代码细节：属于 technical-design 职责
- 本体生成（`ontology-builder`）、在线编辑条目、知识库重命名 / 跨项目转移
- 多用户、角色权限、登录页与登录态本身（复用 workbench-core）
- core 既有页面（首页、会话详情、项目上下文、提供商、调用记录）的布局改版；知识库只提供可挂载区块与会话面板内嵌组件

## 验收标准（EARS 格式）

> 编号接续 workbench-core 的 AC-UX-18，保留 `_handoff/from-interaction-design.md` 已使用的 AC-UX-19 ~ AC-UX-26 原编号；本 spec 新增 27 ~ 30。AC-UX-25 按 2026-11-18 AMB-026 修正为阻塞式确认口径。

### AC-UX-19
WHEN 交互设计完成 THEN 系统 SHALL 在侧边栏「基座管理」分组提供「知识库」入口（与项目上下文 / AI 提供商与模型 / 调用记录同级），并为 US-012 ~ US-016 各提供页面线框图、Mermaid 流程图与 demo 页面；知识库页面 SHALL 复用 core 的 AppShell、`AuthGate`、用户菜单与设计 token，SHALL NOT 另建外壳或配色体系。

### AC-UX-20
WHEN 用户选择知识库文件 THEN 系统 SHALL 逐文件展示校验结果与原因（类型 / 单文件大小 / 数量 / 合计 / 缺少 `index.json`），存在不合规项时禁用「提交导入」；不合规提交 SHALL NOT 写入任何文件或创建知识库，并说明允许范围与上限（`.json` / `.md` / `.markdown`，`index.json` ≤20MB，其他单文件 ≤10MB，单次 ≤50 个，单库合计 ≤100MB）。

### AC-UX-21
WHEN 导入结束 THEN 系统 SHALL 展示导入报告：知识库名与版本、已导入条目数、被跳过条目的行号与原因；同名重新导入 SHALL 提示「已生成 v{N}，旧版本只读保留」；没有任何可导入条目时 SHALL 整体失败并说明已回滚、未创建知识库。

### AC-UX-22
WHEN 用户浏览知识库 THEN 系统 SHALL 支持按项目、知识库、类型筛选与编号前缀 / 完整编号 / 关键词检索，默认展示最新版本；无匹配时 SHALL 展示带「清除筛选」的空态而非错误；条目详情 SHALL 展示字段、表、代码路径、一跳邻居、来源文件与新鲜度，正文缺失时 SHALL 展示摘要并标注「正文缺失」。

### AC-UX-23
WHEN 条目存在新鲜度信息、版本冲突或所属版本已被取代 THEN 系统 SHALL 分别标注「N 天前 / 可能过期 / 未知」「版本冲突（列出来源：知识库名 + 版本 + 生成时间）」「已被新版本取代（提供查看最新版）」，且这些提示 SHALL NOT 阻止浏览或注入；已知为空的字段 SHALL 显示「—」，SHALL NOT 推测填充。

### AC-UX-24
WHEN 用户勾选或取消勾选知识库条目、或修改提示正文 THEN 系统 SHALL 实时展示已选条目数、注入字符数、提示字符数与「合计 / 200,000」；合计超过 90% 时 SHALL 使用警告样式，超过 200,000 时 SHALL 展示提示 / 注入 / 合计 / 上限 / 超出量并禁用「发起调用」，SHALL NOT 静默截断或丢弃条目。

### AC-UX-25
WHEN 用户发起调用且所选条目中存在已删除、已被取代或不存在的条目 THEN 系统 SHALL 在发起外部请求前剔除这些条目并弹出阻塞式确认，列出被剔除的具体编号；用户确认后 SHALL 用其余有效条目照常发起并产生 AiCallRecord，用户取消后 SHALL NOT 发起调用且 SHALL NOT 产生 AiCallRecord；SHALL NOT 静默降级或仅提示后继续。

### AC-UX-26
WHEN 用户从知识库列表行发起删除 THEN 系统 SHALL 先弹出确认对话框，列明级联范围（知识库及其全部版本、条目索引、已存文件、项目关联）并说明历史会话与调用记录不受影响；确认后才执行且无撤销；删除后浏览页不再出现该知识库，历史会话与调用记录中的相关编号 SHALL 标注「知识库已删除」。

### AC-UX-27
WHEN 知识库注入完成一次调用 THEN 系统 SHALL 在会话时间线与调用记录中展示知识库名、版本、编号列表与字符数，SHALL NOT 展示条目正文；知识库已删除时编号旁 SHALL 显示「知识库已删除」。

### AC-UX-28
WHEN 知识库页面在 Light 或 Dark 主题下展示 THEN 系统 SHALL 复用 core 的颜色 / 字体 / 间距 / 圆角 / 阴影 token，不新增 token；正文与背景对比度 SHALL ≥ 4.5:1；知识库文件内容 SHALL 按纯文本展示，SHALL NOT 渲染 HTML。

### AC-UX-29
WHEN demo.html 交付 THEN 系统 SHALL 以单文件、无外部依赖形式覆盖 US-012 ~ US-016 的页面与 default / loading / success / error / empty 五种状态，并提供失效条目阻塞确认、删除确认、明暗主题切换的可交互演示。

### AC-UX-30
WHEN 用户仅使用键盘或视口为 375 / 768 / 1024 / 1440 px THEN 系统 SHALL 提供可见焦点环、Esc 关闭对话框并归还焦点、按钮最小 44×44px、≤768px 侧边栏收起为抽屉，且不出现横向滚动。
