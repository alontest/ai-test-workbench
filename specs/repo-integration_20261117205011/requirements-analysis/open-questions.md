## OQ-RA-REPO-01 目录树是同步时快照还是浏览时实时拉取（AMB-026）

- **状态**：已确认（AMB-026）
- **用户答复**（answers.md 2026-11-18 10:44:10）：「AMB-026（IQ-1）目录树：**浏览时实时逐级拉取**，同步不拉全树。」（同「全按建议」）
- **出处**：
  - AC-019-1：「系统拉取仓库基本信息、全部分支与最近 100 条提交……写入该绑定的元数据快照」
  - AC-019-6：「只有元数据（仓库名 / ID、分支名、提交 sha 与标题、作者、时间、**目录树路径与文件大小**）」
  - AC-021-2：「单个目录的条目数受供应商分页限制时按页加载并提示还有更多」
  - ENT-C14：`kind` 含「目录树」，`truncated` 表示目录树是否被供应商截断
- **影响**：决定同步耗时与限流压力、ENT-C14 的结构与数据量、解绑后目录树能否查看（AMB-031）、`truncated` 的归属（当次响应 vs 快照字段）。

| 选项 | 定义 | 后果 |
|------|------|------|
| **A（建议默认）** | 浏览时实时逐级拉取（按供应商分页）；同步只拉仓库信息、全部分支与最近 100 条提交，不拉全树；ENT-C14 的目录树只记录「按需读取时命中的路径元数据」，不作为全量快照 | 同步更快、限流风险最低；AC-019-6 的「目录树路径与文件大小」需口径修订为「读取时记录」；解绑后目录树不可浏览（与 AMB-031 A 一致） |
| B | 同步时用供应商 recursive 接口拉全树并写入快照 | 满足 AC-019-6 字面；同步耗时与数据量显著上升，GitHub recursive 有 100,000 条目 / 7MB 上限，超限即 truncated；解绑后仍可查目录树 |
| C | 混合：同步只拉默认分支根目录，用户展开时实时拉下一级 | 首屏更快且保留部分快照；实现与缓存语义最复杂，需额外定义快照失效与合并规则 |

- **建议默认值**：A（同步范围与 AMB-023 原文一致；实时拉取才拿得到最新树，且解绑后不保留不可再验证的树数据）

## OQ-RA-REPO-02 分支 / 提交列表读快照还是实时（AMB-027）

- **状态**：已确认（AMB-027）
- **用户答复**（answers.md 2026-11-18 10:44:10）：「AMB-027（IQ-2）分支/提交列表：**实时读取**（不是读快照），保持与目录树同一新鲜度口径；快照只作「对照过哪个提交」的基线证据。」（未采用建议 A 的「读快照」）
- **出处**：
  - AC-020-2：「展示该仓库的分支列表（支持分页与按名称检索）」
  - AC-021-1：「按提交时间倒序展示……并支持翻页」
  - AMB-023 A：「拉取仓库基本信息、全部分支与最近 100 条提交；仓库 / 分支快照全量覆盖，提交滚动保留最近 100 条」
- **影响**：决定浏览时是否还请求供应商、100 条上限与翻页 / 检索的关系、限流压力与「上次同步时间」的含义。

| 选项 | 定义 | 后果 |
|------|------|------|
| **A（建议默认）** | 仓库、分支、提交列表一律读最近一次同步的快照；分支全量、提交最多 100 条；检索与翻页都在本快照内完成，浏览时不再请求供应商 | 与 AMB-023 一致、行为可预期；超过 100 条的提交需重新同步才能看到；分页是本地分页 |
| B | 分支列表实时拉取（支持完整分页），提交读快照 | 分支看到最新，但每次打开选择器都请求供应商，限流与延迟上升；两套数据时效不一致 |
| C | 读快照，并提供「加载更多」按供应商分页实时追加提交（突破 100 条） | 兼顾完整浏览；与 AMB-023「滚动保留 100 条」冲突，需要修订 AMB-023 或明确「加载更多不入快照」 |

- **建议默认值**：A（尊重已确认的 AMB-023，不引入未确认的数据时效差异；需要更多提交时重新同步）

## OQ-RA-REPO-03 保存前能否测试连接（AMB-028）

- **状态**：已确认（AMB-028）
- **用户答复**（answers.md 2026-11-18 10:44:10）：「AMB-028（IQ-3）连接测试：**保存前可用表单当前值测试且不落库**，改字段即失效。理由：与 core 已确认的 UXAMB-006 一致。」（未采用建议 A 的「仅已保存绑定可测」）
- **出处**：
  - US-018 标题：「在**保存前后**测试令牌与仓库是否可用」
  - AC-018-1：「GIVEN 绑定已保存 WHEN 我点击「测试连接」」
  - AC-018-5：「测试成功且随后保存的绑定状态为「已连接」」
- **影响**：表单交互（是否允许未保存凭证发起请求）、接口形态（测试接口是否需要 bindingId）、令牌临时处理的安全约束。

| 选项 | 定义 | 后果 |
|------|------|------|
| **A（建议默认）** | 仅已保存绑定可测试；未保存的表单凭证不发起任何请求、不落库，用户先保存再测试 | 与 AC-018-1 / 018-5 一致；用户需多一步保存；临时凭证不进入任何请求路径，安全面最小 |
| B | 表单内可测试：临时凭证只用于本次只读请求，不落库、不写日志，响应不返回令牌 | 体验最好；需新增「未保存测试」接口并明确临时凭证生命周期与内存处理，安全评审面扩大 |
| C | 保存时自动执行一次测试，测试结果随保存返回 | 减少一步操作；保存变为网络依赖，失败时需区分「未保存」与「已保存但测试失败」 |

- **建议默认值**：A（不改写 AC-018-1 / 018-5；安全边界最小；US-018 标题中的「保存前」按此口径修订）

## OQ-RA-REPO-04 仓库令牌与模型密钥是否共用同一加密密钥（AMB-029）

- **状态**：已确认（AMB-029）
- **用户答复**（answers.md 2026-11-18 10:44:10）：「AMB-029（IQ-4）令牌密钥：独立密钥，环境变量名 `AW_REPO_TOKEN_KEY`，不与模型密钥共用。」
- **出处**：AMB-005 A（加密口令来自环境变量）；决策 16（仓库令牌与模型密钥同级管理）；handoff §8「仓库令牌与模型密钥是否共用同一加密口令 / 密钥未定」
- **影响**：环境变量清单、密钥轮换与回滚、迁移与运维手册；不改变加密算法与掩码口径。

| 选项 | 定义 | 后果 |
|------|------|------|
| **A（建议默认）** | 不共用：仓库令牌使用独立环境变量密钥（建议 `AW_REPO_TOKEN_KEY`，32 字节、base64 编码），缺失时拒绝保存仓库绑定并提示；与 `AW_ENCRYPTION_KEY` 独立轮换 | 轮换模型密钥不影响仓库令牌；运维多一个变量、多一条轮换流程 |
| B | 共用 `AW_ENCRYPTION_KEY` | 变量最少、实现最简；轮换模型密钥会使全部仓库令牌无法解密，需要同时重填所有令牌 |
| C | 一个主密钥 + 按用途派生（如 HKDF 派生子密钥） | 物理只有一个主密钥、逻辑隔离；实现与文档成本略高于 A，轮换仍需重加密 |

- **建议默认值**：A（直接满足「轮换互不影响」，实现最直白；C 可作为技术方案的优化备选）

## OQ-RA-REPO-05 core 项目上下文页「仓库地址」文本框与绑定列表的关系（AMB-030）

- **状态**：已确认（AMB-030）
- **用户答复**（answers.md 2026-11-18 10:44:10）：「AMB-030（IQ-5）「仓库地址」：**单一事实来源** —— 绑定列表为准，文本框降级为自由备注并标注来源。原「并存互不改写」作废。」（未采用建议 A 的「并存」）
- **出处**：workbench-core US-008 / AC-008-2 的「仓库地址」单行文本输入（示例 `git@…:pay.git`）；本 spec AC-017-1 的仓库绑定与列表
- **影响**：项目上下文页字段归属、交互稿是否与 core 稿冲突、用户对「仓库地址」与「绑定仓库」的认知。

| 选项 | 定义 | 后果 |
|------|------|------|
| **A（建议默认）** | 两者并存：「仓库地址」保留为人工备注文本（可填非托管平台地址或多仓库概览），绑定列表独立展示与维护，互不改写 | 与 core 现有页面兼容、无需数据迁移；同一信息可能重复出现，需界面文案区分 |
| B | 绑定列表替代「仓库地址」文本框，既有文本只读保留或迁移为备注 | 页面更简洁；需定义旧值迁移与 core 交互稿同步修改，跨 spec 协调成本高 |
| C | 「仓库地址」改为只读的「绑定摘要」，由绑定列表生成 | 语义最清晰；改变 core 已确认字段的可编辑性，需 core 侧同意 |

- **建议默认值**：A（不改写 core 已确认字段，仓库集成作为增量面板接入；文案说明「仓库地址为人工备注，实际拉取以绑定列表为准」）

## OQ-RA-REPO-06 解绑后目录树与文件读取的只读边界（AMB-031）

- **状态**：已确认（AMB-031）
- **用户答复**（answers.md 2026-11-18 10:44:10）：「AMB-031（IQ-6）解绑后：仓库/分支/提交快照只读可查，目录树与读文件入口置灰。」
- **出处**：
  - AMB-022 A：「保留元数据并标注「已解绑」，只读可查；删除加密令牌，不再同步或读取文件」
  - AC-023-4 / AC-023-5：「已同步元数据保留并标注「已解绑」，只读可查，不再同步或读取文件」
  - 目录树若为浏览时实时拉取（AMB-026 A），解绑后没有可用令牌，无法再拉
- **影响**：解绑后的界面置灰范围、用户的预期管理、ENT-C14 是否需要保留目录树快照。

| 选项 | 定义 | 后果 |
|------|------|------|
| **A（建议默认）** | 解绑后只可查仓库 / 分支 / 提交快照；目录树与文件读取入口置灰、不可发起请求；界面提示「已解绑，目录树与文件读取不可用」 | 与 AMB-026 A 自洽；用户解绑前需自行确认是否还要浏览目录树 |
| B | 解绑后仍可查已同步的目录树快照（依赖 AMB-026 B：同步时拉全树） | 只读范围最大；与 AMB-026 B 绑定，未选 B 时无数据可查 |
| C | 解绑前二次确认中明确告知「解绑后目录树不可浏览」，由用户决定是否先浏览 | 不改变数据边界，只加强提示；可作为 A 的交互补充 |

- **建议默认值**：A（与 AMB-022 的「只读可查」与 AMB-026 A 的实时拉取口径一致；C 作为交互文案建议）
