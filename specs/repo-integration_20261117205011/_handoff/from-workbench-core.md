## 3. 用户故事与 AC 原文

### US-017：绑定云效 / GitHub 仓库并保存访问令牌

**As a** 测试工程师
**I want to** 在项目上下文里绑定被测代码仓库并填写访问令牌
**So that** 后续分析能引用真实的仓库、分支与提交，而不是我手工抄写的仓库地址

**Priority**: P0 | **Related goal**: BG-06

**Acceptance Criteria**:
- **AC-017-1**: GIVEN 我在项目上下文页 WHEN 我选择提供商（云效 Codeup / GitHub）并填写访问令牌（GitHub PAT / 云效个人访问令牌）与仓库标识（云效：组织 ID + 代码库 ID 或 `group/repo` 全路径；GitHub：`owner/repo`），可选填写 API 域名（默认 `https://openapi-rdc.aliyuncs.com`，可填地域域名，AMB-024 已确认）并保存 THEN 系统创建绑定并返回 bindingId，令牌服务端加密存储，列表与详情只显示掩码（如 `ghp_****abcd`），接口响应不返回完整令牌
- **AC-017-2**: GIVEN 必填项缺失、仓库标识格式非法或 API 域名不是 `https://` WHEN 我保存 THEN 系统拒绝并逐字段说明原因，不写入任何绑定或令牌
- **AC-017-3**: GIVEN 同一项目下已存在同一提供商 + 同一仓库的绑定 WHEN 我再次绑定 THEN 系统拒绝并提示重复，原绑定与其令牌保持不变
- **AC-017-4**: GIVEN 绑定已存在 WHEN 我更新访问令牌并保存 THEN 系统只替换加密存储的令牌与掩码，bindingId、已同步元数据与历史记录不变，后续请求使用新令牌
- **AC-017-5**: GIVEN 我在填写绑定 WHEN 页面展示 THEN 明确说明「只读取元数据与按需文件内容，不克隆仓库、不建立代码索引」，并给出最小权限建议（GitHub fine-grained PAT 仅授予目标仓库 Contents 与 Metadata 只读；云效令牌仅授予代码库读取）
- **AC-017-6**: GIVEN 项目已有若干仓库绑定 WHEN 我新增绑定 THEN 系统不设硬性数量上限（0..n），并在界面提示「建议不超过 5 个」以控制同步耗时与限流风险（AMB-025 已确认）

### US-018：测试仓库连通性

**As a** 测试工程师
**I want to** 在保存前后测试令牌与仓库是否可用
**So that** 我不会等到同步或分析时才发现令牌填错或权限不足

**Priority**: P0 | **Related goal**: BG-06

**Acceptance Criteria**:
- **AC-018-1**: GIVEN 绑定已保存 WHEN 我点击「测试连接」 THEN 系统发起一次只读请求（读取仓库基本信息或默认分支），10s 内返回成功（含默认分支，若响应提供则含最近提交时间）或失败原因
- **AC-018-2**: GIVEN 令牌无效、已过期或已被撤销 WHEN 测试 THEN 系统归类为「鉴权失败」，提示重新填写令牌，绑定状态置为「令牌失效」；响应与日志不出现令牌原文
- **AC-018-3**: GIVEN 域名不可达、DNS 解析失败、连接被拒或超时 WHEN 测试 THEN 系统归类为「网络失败」并给出可读原因与重试建议；不写入同步记录、不改变已同步元数据
- **AC-018-4**: GIVEN 令牌有效但无权访问该仓库或所需字段 WHEN 测试 THEN 系统归类为「权限不足」并提示所需只读权限范围，不把权限不足展示为网络失败或令牌无效
- **AC-018-5**: GIVEN 测试已返回 WHEN 我查看绑定 THEN 页面展示测试时间、结果分类与失败原因；测试成功且随后保存的绑定状态为「已连接」，测试不写入会话、制品或 AiCallRecord

### US-019：手动同步仓库元数据

**As a** 测试工程师
**I want to** 手动触发一次元数据同步并看到上次同步时间与结果
**So that** 我知道当前看到的分支与提交是不是最新的，失败时也知道原因

**Priority**: P0 | **Related goal**: BG-06

**Acceptance Criteria**:
- **AC-019-1**: GIVEN 绑定已连接 WHEN 我点击「同步」 THEN 系统拉取仓库基本信息、全部分支与最近 100 条提交（AMB-023 已确认），写入该绑定的元数据快照，完成后展示上次同步时间、耗时与结果
- **AC-019-2**: GIVEN 同一绑定正在同步 WHEN 我再次点击「同步」 THEN 系统返回「同步进行中」并阻止并发同步，不产生第二次同步记录
- **AC-019-3**: GIVEN 同步因鉴权失败、网络失败或供应商限流而失败 WHEN 同步结束 THEN 系统记录失败状态与可读原因，保留上次成功的元数据与上次同步时间，不清空已有元数据
- **AC-019-4**: GIVEN 我打开项目上下文页 WHEN 查看绑定 THEN 系统展示上次同步时间与结果；从未同步时展示「从未同步」而不是空白或错误
- **AC-019-5**: GIVEN 供应商返回限流（如 429 或 `X-RateLimit-Remaining: 0`） WHEN 同步结束 THEN 系统展示「供应商限流」与可重试时间（若响应提供），不自动循环重试、不启动后台轮询
- **AC-019-6**: GIVEN 同步完成 WHEN 检查保存内容 THEN 只有元数据（仓库名 / ID、分支名、提交 sha 与标题、作者、时间、目录树路径与文件大小）；仓库与分支快照全量覆盖，提交滚动保留最近 100 条；不保存代码文件、不建立代码索引；同步不因用户未操作而自动触发（AMB-023 已确认）

- **AC-022-2**: GIVEN 文件大小超过单次读取上限 1 MiB（1,048,576 字节，AMB-020 已确认） WHEN 读取 THEN 系统拒绝并显示文件大小与上限，提示改用更小范围或直接粘贴片段，不截断后冒充完整内容
- **AC-022-3**: GIVEN 文件为二进制或内容不是合法 UTF-8 文本 WHEN 读取 THEN 系统拒绝预览并说明「二进制 / 非文本文件不支持预览」，不把乱码当正文展示
- **AC-022-4**: GIVEN 读取成功 WHEN 我查看 THEN 系统展示文件路径、ref（分支 / commit）、大小、读取时间与内容；内容不写入会话制品与 AiCallRecord，若被引用进分析则按文本输入口径计入 200,000 字符上限

### US-023：处理令牌失效与撤销仓库绑定

**As a** 测试工程师
**I want to** 在令牌失效时收到明确提示，并在不需要时撤销绑定
**So that** 仓库接入不会因为一个过期令牌长期静默失败，撤销后也不留下可用的凭据

**Priority**: P1 | **Related goal**: BG-06

**Acceptance Criteria**:
- **AC-023-1**: GIVEN 同步、浏览或读取文件时供应商返回 401 / 403（鉴权语义） WHEN 系统识别 THEN 将绑定标为「令牌失效」，并在项目上下文页与相关入口提示「令牌失效或权限不足，请重新填写」，不重复弹出多个错误
- **AC-023-2**: GIVEN 绑定已标为「令牌失效」 WHEN 我重新填写有效令牌且测试连接成功 THEN 状态恢复「已连接」，bindingId、已同步元数据与历史记录保持不变
- **AC-023-3**: GIVEN 供应商响应提供令牌过期时间 WHEN 我查看绑定 THEN 系统展示过期时间，并在剩余不足 7 天时提示「即将过期」；无法获得过期时间时不推测
- **AC-023-4**: GIVEN 我要撤销绑定 WHEN 我二次确认撤销 THEN 绑定状态变为「已解绑」，加密令牌被删除且不再发起任何请求；已同步元数据保留并标注「已解绑」，只读可查，不再同步或读取文件（AMB-022 已确认）
- **AC-023-5**: GIVEN 绑定已解绑 WHEN 我查看历史会话、调用记录或仓库元数据 THEN 历史记录不被修改；元数据只读可查、不可再同步或读取文件；已解绑绑定不参与任何 AI 调用
- **AC-023-6**: GIVEN 我重新绑定同一仓库 WHEN 保存成功 THEN 系统生成新的 bindingId 与新令牌，不复用已删除的令牌与旧绑定的同步记录

### EARS 验收标准原文（AC-REQ-25 ~ AC-REQ-35）

#### AC-REQ-25
WHEN 用户为项目绑定云效或 GitHub 仓库并保存访问令牌 THEN 系统 SHALL 创建绑定、以服务端加密存储令牌并只回显掩码，任何接口响应、日志、同步记录与 AiCallRecord 中 SHALL NOT 出现完整令牌；必填缺失或格式非法时 SHALL 拒绝保存且不写入任何数据；同一项目下同一提供商 + 同一仓库 SHALL 唯一；绑定数量 SHALL NOT 设硬上限（0..n），界面 SHALL 提示建议不超过 5 个（AMB-025 已确认）；API 域名 SHALL 默认 `https://openapi-rdc.aliyuncs.com` 并允许填写地域域名（AMB-024 已确认）。

#### AC-REQ-26
WHEN 用户对绑定发起连通性测试 THEN 系统 SHALL 在 10s 内返回「成功 / 鉴权失败 / 网络失败 / 权限不足」之一及可读原因，SHALL NOT 把权限不足归为网络失败，且测试 SHALL NOT 写入会话、制品或 AiCallRecord。

#### AC-REQ-27
WHEN 用户点击「同步」 THEN 系统 SHALL 拉取并保存仓库、全部分支与最近 100 条提交的元数据快照（仓库与分支快照全量覆盖，提交滚动保留最近 100 条），展示上次同步时间、耗时与结果；同一绑定 SHALL NOT 并发同步；失败时 SHALL 保留上次成功元数据与时间；同步 SHALL NOT 由定时任务或后台轮询自动触发。

#### AC-REQ-28
WHEN 供应商返回限流（429 或等价限流信号） THEN 系统 SHALL 展示「供应商限流」与可重试时间（若响应提供），SHALL NOT 自动循环重试或启动后台轮询。

#### AC-REQ-29
WHEN 绑定已同步 THEN 系统 SHALL 允许按名称 / 关键词检索仓库并选择仓库与分支；未同步时 SHALL 展示空态并引导同步；令牌失效时 SHALL 提示并允许查看带上次同步时间标记的缓存元数据。

#### AC-REQ-30
WHEN 用户按分支查看提交与目录树 THEN 系统 SHALL 展示提交 sha 短号、标题、作者、时间与目录 / 文件层级（名称、类型、大小）；供应商标记目录树被截断时 SHALL 提示「目录树不完整」，SHALL NOT 把不完整结果当完整结果。

#### AC-REQ-31
WHEN 用户读取单个文件 THEN 系统 SHALL 通过供应商 API 按指定 ref 读取并展示内容，SHALL NOT 克隆仓库或建立代码索引；文件超过单次读取上限 1 MiB（1,048,576 字节，AMB-020 已确认）时 SHALL 拒绝并显示大小与上限；二进制或非 UTF-8 内容 SHALL 拒绝预览；路径含 `..`、绝对路径或非法 ref 时 SHALL 在发起请求前拒绝。

#### AC-REQ-32
WHEN 供应商返回鉴权失败 THEN 系统 SHALL 将绑定标为「令牌失效」并在相关入口提示重新填写；系统 SHALL NOT 自动轮换令牌或代用户续期（AMB-021 已确认）；用户更换有效令牌且测试成功后 SHALL 恢复「已连接」并保留原绑定与已同步元数据；供应商提供过期时间时 SHALL 展示，剩余不足 7 天时提示「即将过期」，无数据时 SHALL NOT 推测。

#### AC-REQ-33
WHEN 用户撤销绑定 THEN 系统 SHALL 将状态置为「已解绑」并删除加密令牌，此后 SHALL NOT 再发起任何请求；已同步元数据 SHALL 保留并标注「已解绑」，只读可查、不再同步或读取文件（AMB-022 已确认）；历史会话、制品与 AiCallRecord SHALL NOT 被修改；重新绑定同一仓库 SHALL 生成新绑定与新令牌。

#### AC-REQ-34
WHEN 系统执行仓库同步或文件读取 THEN 系统 SHALL 只保存元数据（仓库 / 分支 / 提交 / 目录树路径与大小），SHALL NOT 把仓库代码落盘、建立代码索引或写入会话制品，SHALL NOT 把元数据与文件内容写入 AiCallRecord 正文；文件内容若被引用进分析，其字符数 SHALL 计入 200,000 字符上限。

#### AC-REQ-35
WHEN 用户保存仓库绑定或填写令牌 THEN 系统 SHALL 提示使用只读最小权限令牌，且系统 SHALL NOT 发起任何仓库写操作（创建分支、提交、合并请求或评论）。

## 4. 涉及实体与业务规则原文

### 实体

#### ENT-C12 代码仓库绑定（CodeRepoBinding）
- **对应图谱**：未覆盖
- **定义**：项目与一个外部代码仓库（云效 Codeup 或 GitHub）之间的只读绑定关系，持有该仓库的访问令牌与最近一次同步状态；是元数据同步、分支选择与按需读文件的入口
- **关键属性**：bindingId、projectId、provider（yunxiao / github）、apiBaseUrl、orgId（云效）/ owner（GitHub）、repoId / repoName、displayName、tokenCiphertext、tokenMasked、tokenExpiresAt（可空）、status（未验证 / 已连接 / 令牌失效 / 已解绑）、lastVerifiedAt、lastSyncAt、lastSyncStatus、createdAt、updatedAt；同一项目下同一提供商 + 同一仓库唯一
- **所属模块**：workbench-core（迁出后应为 repo-integration）
- **来源 spec**：ai-test-workbench_20261117184149

#### ENT-C13 仓库同步记录（RepoSyncRecord）
- **对应图谱**：未覆盖
- **定义**：一次手动同步的执行记录，用于展示上次同步时间、结果与失败原因；不保存令牌与供应商响应原文
- **关键属性**：syncId、bindingId、startedAt、finishedAt、status（成功 / 失败）、repoCount、branchCount、commitCount、errorCategory（鉴权 / 网络 / 限流 / 其他）、errorMessage、createdAt
- **所属模块**：workbench-core（迁出后应为 repo-integration）

#### ENT-C14 仓库元数据快照（RepoMetadataSnapshot）
- **对应图谱**：未覆盖
- **定义**：同步得到的仓库、分支、提交与目录树元数据集合，供选择器与浏览页读取；只含元数据，不含代码文件内容
- **关键属性**：snapshotId、bindingId、repoId、kind（仓库 / 分支 / 提交 / 目录树）、ref（分支 / tag / commit）、payload（名称、ID、sha、标题、作者、时间、路径、文件大小）、fetchedAt、truncated（目录树是否被供应商截断）
- **所属模块**：workbench-core（迁出后应为 repo-integration）

#### ENT-C15 仓库文件读取记录（RepoFileReadRecord）
- **对应图谱**：未覆盖
- **定义**：一次按需读取单个文件的审计记录，只记录读取目标与结果，不保存文件正文
- **关键属性**：readId、bindingId、repoId、ref、filePath、byteSize、encoding（text / base64）、status（成功 / 拒绝）、rejectReason（超限 / 二进制或非 UTF-8 / 非法路径）、fetchedAt
- **所属模块**：workbench-core（迁出后应为 repo-integration）

### 业务规则

#### BR-C21 仓库绑定与令牌只读最小权限
- **对应图谱**：未覆盖
- **规则**：项目可绑定 0..n 个云效 / GitHub 仓库，同一项目下同一提供商 + 同一仓库唯一；访问令牌沿用 AMB-005 服务端加密存储、掩码回显，令牌原文与鉴权请求头不得出现在日志、错误响应、同步记录与 AiCallRecord；界面提示使用只读最小权限令牌，系统不发起任何仓库写操作；绑定数量不设硬上限（0..n），界面提示建议 ≤ 5 个（AMB-025）；云效默认域名 `https://openapi-rdc.aliyuncs.com` + `/oapi/v1/codeup`，允许填地域域名（AMB-024）
- **约束对象**：ENT-C12、ENT-C1

#### BR-C22 连通性测试四类结果
- **对应图谱**：未覆盖
- **规则**：连通性测试只发起一次只读请求并在 10s 内返回，结果分为成功 / 鉴权失败 / 网络失败 / 权限不足四类；权限不足不得归为网络失败，网络失败不得归为令牌无效；测试不写会话、制品或 AiCallRecord
- **约束对象**：ENT-C12

#### BR-C23 手动同步元数据且不克隆不建索引
- **对应图谱**：未覆盖
- **规则**：同步只由用户点击触发，同一绑定禁止并发；一次同步保存仓库、全部分支与最近 100 条提交（AMB-023）的元数据快照，仓库 / 分支快照全量覆盖、提交滚动保留 100 条，不保存代码文件、不建立代码索引、不做定时任务与 Webhook；失败时保留上次成功元数据与上次同步时间，并记录错误分类
- **约束对象**：ENT-C12、ENT-C13、ENT-C14

#### BR-C24 仓库与分支选择及目录树浏览
- **对应图谱**：未覆盖
- **规则**：仓库与分支只能从已同步元数据中选择，默认选中绑定仓库与默认分支；未同步时展示空态并引导同步；目录树被供应商标记为截断时必须提示「目录树不完整」，不得把不完整结果当完整结果
- **约束对象**：ENT-C14

#### BR-C25 按需读取单文件的边界
- **对应图谱**：未覆盖
- **规则**：文件内容只经供应商 API 按指定 ref 读取单个文件；超过单次读取上限 1 MiB（AMB-020）拒绝并显示大小与上限；二进制或非 UTF-8 内容拒绝预览；路径含 `..`、绝对路径或 ref 非法时在发起请求前拒绝；内容不落盘、不写会话制品与 AiCallRecord，引用进分析时计入 200,000 字符上限
- **约束对象**：ENT-C12、ENT-C15

#### BR-C26 令牌失效与过期提示
- **对应图谱**：未覆盖
- **规则**：供应商返回鉴权失败时把绑定标为「令牌失效」并在相关入口统一提示重新填写；更换有效令牌且测试成功后恢复「已连接」，保留 bindingId 与已同步元数据；供应商提供过期时间时展示，剩余不足 7 天提示「即将过期」，无数据时不推测
- **约束对象**：ENT-C12

#### BR-C27 撤销绑定与元数据保留
- **对应图谱**：未覆盖
- **规则**：撤销绑定需二次确认，状态置「已解绑」并删除加密令牌，此后不再发起任何请求；已同步元数据保留并标注「已解绑」、只读可查（AMB-022），历史会话、制品与 AiCallRecord 不变；重新绑定同一仓库生成新 bindingId 与新令牌
- **约束对象**：ENT-C12、ENT-C13、ENT-C14

### 术语（原 glossary.md）

- TERM-C14 仓库绑定（Repository Binding）：项目与一个外部代码仓库（云效 Codeup 或 GitHub）之间的只读关联，包含提供商、仓库标识、加密访问令牌与最近同步状态；一个项目可有 0..n 个绑定。避免叫法：仓库连接、代码接入、克隆任务。
- TERM-C15 仓库元数据同步（Repository Metadata Sync）：用户手动触发的一次只读拉取，获取仓库、分支、最近提交与目录树元数据并保存为快照；不是克隆，不下载代码文件，不建立代码索引。避免叫法：仓库克隆、代码同步、拉取代码。
- TERM-C16 按需文件读取（On-demand File Read）：用户选定目录树中的单个文件与 ref 后，经供应商 API 读取一次文件内容用于查看或分析引用；受单文件大小上限与 UTF-8 文本限制，内容不落盘。避免叫法：文件下载、缓存文件、代码索引。

### 业务流程（原 processes.md）

- BP-C9 仓库绑定与连通性测试：触发条件 = 用户在项目上下文页填写提供商、令牌与仓库标识并保存，或点击「测试连接」；操作对象 = ENT-C12（创建或更新绑定、加密令牌、记录测试结果与状态）；测试只发一次只读请求，10s 内返回四类结果之一。
- BP-C10 仓库元数据手动同步：触发条件 = 用户点击「同步」；操作对象 = ENT-C12（更新上次同步时间与状态）、ENT-C13（写入同步记录）、ENT-C14（写入仓库 / 分支 / 提交 / 目录树元数据快照）；失败保留旧快照，不克隆、不建索引。
- BP-C11 按需读取仓库文件：触发条件 = 用户在目录树或提交中选定单个文件与 ref 并请求查看；操作对象 = ENT-C12（读取绑定令牌）、ENT-C15（记录读取目标与结果）；内容经供应商 API 读取，不落盘、不写会话制品与 AiCallRecord。

## 5. 流程图要点（原 docs/flowchart.md 对应 US 的 mermaid）

- **US-017 绑定**：打开项目上下文页 → 选择提供商（云效 Codeup / GitHub）→ 填写访问令牌与仓库标识 → 可选填 API 域名 → 必填完整且格式合法（否则逐字段提示，不写入）→ 同项目同提供商 + 同仓库已绑定（否则拒绝、原绑定不变）→ 加密存储令牌 → 创建绑定返回 bindingId → 只回显掩码 → 提示只读最小权限、说明不克隆不建索引。

- **US-020 选择仓库与分支**：打开选择器 → 元数据未同步则空态引导先同步 → 令牌失效则提示并可重填，仍可看缓存元数据并标注上次同步时间 → 按名称/关键词检索并选仓库 → 分支列表默认选中默认分支 → 切换分支后提交与目录树随之切换。

- **US-023 失效与撤销**：401/403 → 绑定标「令牌失效」→ 相关入口统一提示重填 → 填新令牌并测试成功则恢复「已连接」并保留 bindingId 与元数据；或二次确认撤销 → 状态「已解绑」、删除加密令牌、不再发请求 → 元数据保留标「已解绑」、历史记录不变 → 重新绑定生成新绑定与新令牌。

## 7. 已核实的接口事实（原 design.md「外部接口核实（研究与复用，2026-11-17）」原文）

本节记录本轮为仓库集成需求实际核实的供应商接口事实，供技术方案阶段直接引用。**未核实项已标注，不得据此编造端点或限流数值。**

### GitHub REST API（已核实）

- 鉴权：`Authorization: Bearer <token>`（PAT）。来源：GitHub 官方 REST 文档「Authenticating to the REST API」（`docs.github.com/en/rest/authentication/authenticating-to-the-rest-api`）。
- 端点与方法（来源：官方 OpenAPI 描述 `github/rest-api-description` 的 `api.github.com.json`，逐条核对 path 与方法存在）：
  - 仓库列表 `GET /user/repos`（当前令牌可见仓库）；仓库详情 `GET /repos/{owner}/{repo}`
  - 分支 `GET /repos/{owner}/{repo}/branches`、`GET /repos/{owner}/{repo}/branches/{branch}`
  - 提交 `GET /repos/{owner}/{repo}/commits`、`GET /repos/{owner}/{repo}/commits/{ref}`
  - 目录树 `GET /repos/{owner}/{repo}/git/trees/{tree_sha}`（支持 `recursive`；响应含 `truncated`；官方文档注明 recursive 时上限 100,000 条目 / 7MB）
  - 文件内容 `GET /repos/{owner}/{repo}/contents/{path}`（`ref` 参数指定分支 / tag / commit）
- 文件大小：官方文档注明 1 MB 及以下支持该端点全部能力，1–100 MB 只支持 raw / object 媒体类型，因此单次读取上限取 1 MiB 与供应商能力对齐（AMB-020 已确认）。
- 限流：PAT 认证 5,000 请求/小时，未认证 60 请求/小时（来源：官方「Rate limits for the REST API」文档）；响应含 `X-RateLimit-Remaining` / `X-RateLimit-Reset`。
- 未核实：令牌过期时间响应头的具体名称与语义、fine-grained PAT 对 Contents / Metadata 权限的精确映射——留待 tech-arch 依据官方文档确认。

### 阿里云云效（Codeup）OpenAPI（已核实）

- 鉴权：请求头 `x-yunxiao-token: <个人访问令牌>`（不是 Bearer）。来源：`aliyun/alibabacloud-devops-mcp-server` 的 `common/utils.ts`（`requestHeaders["x-yunxiao-token"] = token`），该仓库为阿里云官方维护的 MCP server。
- 默认 API 域名：`https://openapi-rdc.aliyuncs.com`；地域版实例使用自有域名，路径不带 `organizations/{orgId}` 段（同上源码）。
- 端点（中心站形态，均前缀 `/oapi/v1/codeup`）：
  - 仓库列表 `GET /oapi/v1/codeup/organizations/{orgId}/repositories`（`page`、`perPage`、`search`、`archived`、`orderBy`、`sort`）
  - 仓库详情 `GET .../repositories/{repoId}`（repoId 支持数字 ID 或 URL 编码的 `group/repo` 全路径）
  - 分支列表 `GET .../repositories/{repoId}/branches`（`page`、`perPage`、`sort`、`search`）
  - 提交列表 `GET .../repositories/{repoId}/commits`（`refName` 必填，`since` / `until`、`page`、`perPage`、`path`、`search`）
  - 目录树 `GET .../repositories/{repoId}/files/tree`（`path`、`ref`、`type` = `DIRECT` / `RECURSIVE` / `FLATTEN`）
  - 单文件内容 `GET .../repositories/{repoId}/files/{filePath}`（`ref` 必填；响应含 `content`、`size`、`encoding`，编码可为 `text` 或 `base64`）
- 分页：响应头 `x-total` / `x-page`，不是响应体字段；实现必须能读响应头。
- 未核实：官方速率限制数值、单文件大小上限、令牌最小权限的官方表述（官方帮助页为脚本渲染，本轮未取到正文）——留待 tech-arch 研究，不得假设具体数值；本 spec 只要求「限流时展示可读原因与可重试时间」。

### 复用结论

- 云效侧直接复用阿里云官方 MCP server 的端点定义与编码规则（repoId / filePath 的 URL 编码、region 与中心站双形态），不自行猜路径。
- GitHub 侧以官方 OpenAPI 描述为准，端点与方法均已逐条核对；限流与 1 MB 边界作为需求约束写入。
- 两侧都需要「读响应头」的能力（分页与限流），因此技术方案中的 HTTP 客户端必须暴露响应头，不能只返回 body。

### 非功能需求原文（仓库集成与令牌安全）

- 令牌存储：GitHub PAT 与云效个人访问令牌沿用 AMB-005 口径——服务端加密存储，加密口令来自环境变量；列表、详情、错误响应与日志只回显掩码（如 `ghp_****abcd`、`****`），任何接口都不返回完整令牌。
- 令牌不落日志：令牌原文、Authorization / `x-yunxiao-token` 请求头、请求 URL 中的凭据参数不得出现在应用日志、错误响应、同步记录、文件读取记录与 AiCallRecord 中；日志只允许记录绑定 ID、提供商、仓库标识、状态码与错误分类。
- 最小权限：界面须提示建议使用**只读**令牌（GitHub fine-grained PAT 仅授予目标仓库的 Contents 与 Metadata 只读；云效个人访问令牌仅授予代码库读取），工作台不会请求写权限，也不做任何写操作。
- 连通性测试：只发起一次只读请求，10s 内返回；结果分为「成功 / 鉴权失败 / 网络失败 / 权限不足」四类，不把权限不足归为网络失败，也不把网络失败归为令牌无效。
- 单次文件读取上限：单个文件超过 1 MiB（1,048,576 字节，与 GitHub contents API 的 1MB 完整支持边界对齐，AMB-020 已确认）时拒绝读取并提示文件大小与上限，不截断后冒充完整内容；云效侧同一上限，超限时先取文件大小再判断。
- 编码与类型：只读取 UTF-8 文本；供应商返回 base64 或标记为二进制时按二进制处理并拒绝预览。非 UTF-8 内容不得以乱码形式展示为正文。
- 路径与引用校验：文件路径不得包含 `..`、绝对路径或以 `\0` 结尾；ref（分支 / tag / commit）按供应商允许的字符集校验；路径与 ref 作为查询参数时须正确编码，禁止拼接未编码内容。
- 供应商限流：遇到 429 或等价限流响应时，展示「供应商限流」、可重试时间（若响应提供）与建议操作；同一绑定不自动循环重试，不做后台轮询。
- 数据边界：元数据与文件内容**不写入 AiCallRecord 正文**，也不写会话制品；文件内容只在读取请求与页面展示期间存在，若被引用进分析，按文本输入口径计入 200,000 字符上限（AMB-010）。
- 不克隆、不建索引：不把仓库代码落到本地磁盘、不建立代码索引或向量库；同步只保存元数据快照（名称、ID、分支、提交 sha / 标题 / 作者 / 时间、目录树路径）。
- 外部输入校验：仓库、分支、提交与目录树响应按不可信外部输入处理，字段缺失或类型不符时按「未知」展示并记录可读错误，不把原始响应回显到界面。
