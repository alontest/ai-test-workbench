# Interaction Design — Design

本 spec（`repo-integration`）的交互设计是 `workbench-core` 的**增量**：沿用其 AppShell、三区布局、Dark-first 近黑中性基调与全部既有 Design Tokens；只新增「仓库绑定」面板、「仓库浏览」页面、文件查看抽屉与 3 个 token。core 页面的线框不在本文件重画。

## 设计决策

### 决策 1：沿用 workbench-core 设计系统与 AppShell，只交付增量

- **选择**：复用 core 的侧边栏（248px，含「基座管理」分组）、顶栏（64px）、内容区（最大 1280px）、Light/Dark 两套 token、以及 `FormField` / `ConfirmDialog` / `Toast` / `EmptyState` / `ErrorState` / `Skeleton` / `StatusPill` 的既有语义。新增界面只使用这些 token 与组件语义。
- **理由**：用户已定「扩展 core 现有线框…不重做 core 页面、不另建配色与组件体系」；仓库绑定与项目资料在同一页面出现，两套视觉会破坏一致性；core 的明暗对比度已实测达标。
- **备选**：新建「仓库管理」一级导航与独立视觉体系。
- **权衡**：项目上下文页信息密度上升。用「项目列表 / 项目详情」两栏保持 core 现状，仓库绑定作为详情表单下方的纵向区块、同步记录折叠、浏览独立路由来分摊。
- **来源**：`specs/ai-test-workbench_20261117184149/interaction-design/{design.md,docs/design-system.md}`。

### 决策 2：仓库集成作为项目详情表单下方的纵向区块

- **选择**：`/projects` 页保留 core 的「左项目列表 / 右项目详情表单」两栏；在项目详情表单下方增加整行「仓库绑定」区块：说明 → 绑定列表 → 新增 / 更新令牌表单（就地展开）。≤1180px 时项目列表、项目详情与仓库绑定依次堆叠。
- **理由**：core 项目上下文页已经是「左项目列表 / 右项目详情表单」两栏，再横向切一次会变三栏，挤压绑定列表与操作；纵向区块正好承接表单里的「仓库地址」字段（AMB-030 已降级为自由备注，绑定列表是唯一来源）；用户在同一个页面完成「绑定 → 测试 → 同步 → 浏览」，不跳页。
- **备选**：在右列下方再切一列（三栏）；项目上下文页加「仓库」页签。
- **权衡**：页面纵向变长，需要滚动；但仓库绑定获得整行宽度，绑定行、操作与同步记录不拥挤，≤1180px 时按项目列表 → 项目详情 → 仓库绑定顺序堆叠。

### 决策 3：浏览与读文件使用独立路由 `/projects/:projectId/repos/:bindingId`

- **选择**：绑定行「浏览」进入仓库浏览页；页内有面包屑返回项目上下文，绑定摘要与状态常驻顶部。
- **理由**：提交分页、目录树逐级展开、文件抽屉三种高频操作在项目表单页内展开会互相挤压；独立路由也让「令牌失效 / 已解绑」的只读提示有稳定落点。
- **备选**：页内抽屉全屏展开；弹窗嵌套。
- **权衡**：多一次导航，但用面包屑与「返回」按钮消除迷失；不复制项目表单，避免两处编辑同一数据。

### 决策 4：以绑定行为状态中心，四态徽标 + 单一失效横幅

- **选择**：绑定状态统一为「未验证 / 已连接 / 令牌失效 / 已解绑」，绑定行首展示状态徽标；令牌失效时项目上下文页顶部只出现**一条**聚合横幅（列出受影响绑定并提供「重新填写令牌」），不在每个操作上重复弹错。
- **理由**：AC-023-1 要求「统一提示重填，不重复弹错」；把状态放在绑定行上，用户能直接定位是哪条绑定失效。
- **备选**：每条操作各自 toast；全局红点。
- **权衡**：横幅只在存在「令牌失效」绑定时出现；无失效绑定不占空间。

### 决策 5：测试连接复用 core 的 `ConnectionTestBadge`，改字段即失效（AMB-028）

- **选择**：表单内「测试连接」按钮下方**复用 core 的 `ConnectionTestBadge`**（不另做结果条组件），在其后接测试时间、可读原因与下一步；四类结果使用该徽标的既有语义色。表单任一字段变更后徽标不消失，转灰并标「已失效（时间 · 结果）」。
- **理由**：AMB-028 已确认「保存前可用表单当前值测试且不落库，改字段即失效」；core 已有测试结果组件，复用可保持提供商页与仓库绑定页一致；保留上次结果并标失效，比直接清空更能防止用户误以为从未测试。
- **备选**：新做 `ConnectionTestStrip`；改字段即清空结果。
- **权衡**：`ConnectionTestBadge` 需扩展 `permission-denied` 与 `stale` 两个状态（权限不足不能归入 auth-error 或 unreachable）；不落库、不写日志，令牌不进入界面。

### 决策 6：实时读取与基线对照在视觉上分开

- **选择**：仓库 / 分支 / 提交列表与目录树标注「实时读取」；同步产生的快照以「上次同步基线 `<ref> @ <sha> · <时间>`」单独一行展示，并注明「仅作对照与失效时的 last-known」。令牌失效时浏览页明确提示「当前为上次同步基线」。
- **理由**：AMB-026 / AMB-027 已确认浏览实时、同步只存基线；两种数据混在一起会让用户误判新鲜度。
- **备选**：浏览时同时展示快照与实时两份列表。
- **权衡**：多一行基线信息；但避免了两份相似列表的认知负担。

### 决策 7：解绑二次确认，快照只读、入口置灰

- **选择**：解绑必须经 `ConfirmDialog`，逐条列出后果（删令牌、不再请求、快照只读、目录树与读文件置灰、历史不变、重新绑定生成新 bindingId）。确认后绑定行保留在主列表，整行置灰、令牌显示「—」，操作只剩「查看快照 / 重新绑定」；浏览页目录树行与读文件入口 `aria-disabled` 且不可点击。
- **理由**：AC-023-4 / AMB-031 已确认；隐藏已解绑绑定会让用户无法回看历史快照，置灰比隐藏更可解释。
- **备选**：解绑后从列表移除；归档到「已解绑」折叠区。
- **权衡**：列表会保留历史绑定；用置灰与状态徽标区分，并在页脚说明「已解绑不参与任何 AI 调用」。

### 决策 8：错误分级，避免模态堆叠

- **选择**：字段级错误贴在字段下；区块级失败（列表加载、实时读取）用区块内 `ErrorState` + 重试；跨区块的令牌失效用页面横幅；成功只用 `Toast`，失败不用 Toast 重复播报。破坏性操作用模态，普通错误不用模态。
- **理由**：core 的既有约定；AC-023-1 明确不重复弹错；原型中同一时刻最多一个模态（解绑确认）。
- **备选**：所有失败统一 Toast。
- **权衡**：错误出现位置分散，但每个错误都靠近它的触发点。

## 设计系统

**来源**：沿用 `workbench-core`（`specs/ai-test-workbench_20261117184149/interaction-design/design.md`「设计系统」与 `docs/design-system.md`）。本 spec **未重新选型**，也未运行 `ui-ux-pro-max` 生成新风格（该 skill 仅用于全新模块；本模块已有继承的设计系统）。

| 项 | 沿用内容 | 本 spec 的用法 |
|----|---------|---------------|
| 风格 | Dark-first 工程师工作台；暗色近黑中性（背景 `#0A0A0B`、卡片 `#141416`、弱化 `#1C1C1F`、边框 `#2A2A2E`） | 项目上下文页与浏览页全部沿用 |
| 配色 | 主色、强调绿、危险红、警告琥珀、信息蓝；Light 为 slate 体系 | 绑定状态、四类测试结果、截断与限流提示直接映射既有语义色 |
| 字体 | 正文 IBM Plex Sans；标题与代码 JetBrains Mono | 仓库全名、分支、sha 短号、路径、文件内容用 mono |
| 效果 | 150–240ms 过渡、轻阴影、无弹跳 | 抽屉与确认框用既有 `--shadow-lg` 与 `--duration-slow` |
| 布局 | 248px 侧边栏、64px 顶栏、1280px 内容区 | 浏览页沿用；文件抽屉新增 480px 宽度 token |
| 反模式 | 默认浅色、重阴影、emoji 图标、hover-only 交互、移除焦点环 | 仓库面板不使用 emoji；目录树图标用文本 `DIR` / `FILE` |

**States**：
- default：项目列表 / 项目详情 + 仓库绑定区块（含四种状态行）
- loading：绑定列表骨架（标题 + 3 张卡片骨架），项目区块不重新加载
- success：同步完成后展示成功横幅「同步完成 · 耗时 · 基线已更新」
- error：绑定列表加载失败 → 区块内 `ErrorState` + 「重试」；字段错误与测试失败不使用本状态
- empty：无绑定 → 「还没有绑定仓库」+「+ 添加绑定」+ 说明「未同步时浏览为空态」

**Purpose**：新增绑定或更新令牌，支持保存前用当前表单值测试连接且不落库。

**Layout**：
```
+------------------------------------------------------------------+
| 添加仓库绑定 / 更新访问令牌                                [关闭] |

| [测试连接]  一次只读请求 · 10s 超时 · 不落库                       |
| [ConnectionTestBadge：成功 / 鉴权失败 / 网络失败 / 权限不足 / 已失效] |

+------------------------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 提供商 | Segmented control | 云效 Codeup / GitHub；切换后仓库标识占位与 API 域名默认值随之变化；GitHub API 域名固定只读 |
| 仓库标识 | Text input | 必填；GitHub 校验 `owner/repo`；云效接受 `group/repo` 或组织 ID + 代码库 ID；就近展示错误 |
| API 域名 | URL input | 云效默认 `https://openapi-rdc.aliyuncs.com`，允许地域域名；必须 `https://`；GitHub 只读 `https://api.github.com` |
| 访问令牌 | Password input | 新建必填；编辑时留空表示不修改；placeholder 与 hint 只出现掩码，不出现完整令牌 |
| 最小权限说明 | Info banner | 固定展示只读权限建议与「不克隆仓库、不建立代码索引」 |
| 测试连接 | Secondary button | 用当前表单值发起一次只读请求；测试中禁用并显示「测试中」；不落库、不写日志 |
| ConnectionTestBadge（复用 core） | Badge + 说明 | 四类结果之一 + 测试时间 + 原因 + 下一步；字段变更后转灰并标「已失效（时间 · 结果）」；扩展 `permission-denied` 与 `stale` 状态 |
| 保存 | Primary button | 校验通过后创建绑定或更新令牌；重复绑定拒绝并保留原绑定；成功后关闭表单并 Toast |
| 取消 / 关闭 | Button | 丢弃未保存输入；不提示确认（未落库） |

**States**：
- default：新建表单（云效默认，API 域名预填）
- loading：测试中（按钮禁用 + `ConnectionTestBadge` 显示「测试中」）；保存中按钮内联 loading（实现时沿用 core 按钮约定）
- success：`ConnectionTestBadge` 显示「成功」+「默认分支 main」；保存后 Toast「已保存绑定，令牌仅显示掩码」
- error：字段级错误（必填 / 格式 / 重复）；测试结果「鉴权失败 / 网络失败 / 权限不足」
- empty：不适用（表单本身不出现空态；未填写字段用 hint 而非空态）

### 连通性测试结果（复用 core `ConnectionTestBadge`，US-018）

**Purpose**：把四类结果与下一步动作固定在同一位置，避免用户把权限不足误判为令牌无效或网络问题。

**Layout**：
```
+---------------------------------------------------------------------------+
| [成功]     2026-11-18 10:52                                               |
|            默认分支 main，最近提交 11-18 09:21                             |
|            保存后状态为「已连接」。                                        |
+---------------------------------------------------------------------------+
| [鉴权失败] 2026-11-18 10:52                                               |
|            401：令牌已过期或被撤销，请重新填写                              |
|            请重新填写令牌；保存前测试不落库。                               |
+---------------------------------------------------------------------------+
| [权限不足] …  403：令牌有效但无权访问该仓库，请检查只读权限范围              |
|            GitHub 授予 Contents/Metadata 只读；云效授予代码库读取。         |
+---------------------------------------------------------------------------+
| [网络失败] …  域名不可达 / DNS 失败；未写同步记录，未改动已同步元数据        |
+---------------------------------------------------------------------------+
| [已失效（时间 · 结果）] 表单字段已修改，请重新测试；上一次结果仅作参考。 |
+---------------------------------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 结果徽标 | Status pill | 成功 = success；鉴权失败 = destructive；权限不足 = warning；网络失败 = warning；已失效 = muted |
| 测试时间 | Mono text | 每次测试刷新；不写同步记录 |
| 原因与下一步 | Text | 四类结果使用不同文案，禁止互相归类 |
| 去重约束 | — | 同一绑定同一次测试只出现一个 `ConnectionTestBadge`；不弹 Toast、不写会话 / 制品 / AiCallRecord |

**States**：idle（未测试，无徽标）/ testing / success / auth-error / unreachable / timeout / permission-denied / stale（已失效）/ empty（不适用）。

### 同步控件与同步记录（US-019）

**Purpose**：手动触发基线同步，展示上次同步时间、耗时与结果；失败保留旧基线。

**Layout**：
```
+-----------------------------------------------------------------------+
| 绑定行：[同步]  ← 未同步时为主按钮；同步中为「同步中…」且禁用             |
| 上次同步 2026-11-18 09:40 · 耗时 6.2s · 成功                            |
| 基线 main @ a1b2c3d · 2026-11-18 09:40 · 仅作对照与失效时的 last-known   |
| [查看同步记录]                                                          |
|   +-----------------------------------------------------------------+  |
|   | 开始时间        | 耗时  | 结果         | 说明                    |  |
|   | 11-18 09:40    | 6.2s | 成功         | 仓库 1 · 分支 18 · 提交 100 |  |
|   | 11-18 08:12    | —    | 鉴权失败     | 保留上次成功基线与时间      |  |
|   | 11-17 18:40    | 4.1s | 供应商限流   | 可重试 18:42（未自动重试）  |  |
|   +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 同步按钮 | Primary button | 每次点击触发一次同步；同一绑定同步中禁用并显示「同步中…」；不自动重试、不后台轮询 |
| 上次同步 | Static text | 时间 · 耗时 · 结果；从未同步显示「从未同步」 |
| 基线 | Static text（mono） | `ref @ sha · 时间 · 仅作对照与失效时的 last-known` |
| 同步记录 | Collapsible table | 开始时间 / 耗时 / 结果 / 说明；失败行说明「保留上次成功基线与时间」；限流行写可重试时间 |
| 失败提示 | Banner / inline | 鉴权失败、网络失败、供应商限流分别给可读原因；失败不清空已有元数据 |

**States**：default（从未同步）/ syncing（按钮禁用 + 徽标「同步进行中」）/ success（更新基线 + 横幅）/ error（失败原因 + 上次成功时间保留）/ empty（无记录：显示「还没有同步记录」）。

### 仓库与分支选择器（US-020）

**Purpose**：在浏览页选择仓库与分支，默认绑定仓库与默认分支；列表实时读取、支持检索与分页。

**Layout**：
```
+-----------------------------------------------------------------------------+
| 仓库（实时）                    | 分支（实时，分页）            | [刷新]      |
| [pay/checkout（默认）        v] | [main（默认）               v] |             |
| 按名称 / 关键词检索；默认绑定仓库 | 默认选中默认分支；切换后提交与目录树切换 |             |
+-----------------------------------------------------------------------------+
| 上次同步基线 main @ a1b2c3d · 2026-11-18 09:40 · 仅作对照                    |
+-----------------------------------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 仓库选择器 | Select + search | 实时请求供应商仓库列表；按名称 / 关键词检索；默认选中绑定配置的仓库 |
| 分支选择器 | Select | 实时展示分支（供应商分页、按名称检索）；默认选中默认分支并标「（默认）」；切换后提交与目录树重新加载 |
| 刷新 | Secondary button | 重新拉取当前仓库 / 分支的实时数据；不触发同步、不写快照 |
| 实时标记 | Static text | 「实时读取」常驻，避免与基线混淆 |
| 未同步空态 | EmptyState | 「还没有可浏览的元数据」+「去同步」；不返回错误页 |
| 令牌失效提示 | Banner（error）+ 基线标记 | 提示重填，同时展示上次同步基线与时间；不阻止查看基线 |

**States**：default / loading（选择器骨架 + 禁用）/ success（列表已刷新横幅）/ error（供应商不可达 + 重试；已保存数据不动）/ empty（未同步或列表为空）。

### 提交列表与目录树（US-021）

**Purpose**：按分支实时查看提交与目录层级，定位变更与文件路径。

**Layout**：
```
+------------------------------------+  +--------------------------------------+
| 目录树                 逐级实时读取 |  | 提交                 按时间倒序 · 实时分页 |
| ▾ DIR src/                    目录 |  | [a1b2c3d] fix(pay): 回调签名校验顺序调整 |
|    FILE main.py             8.6 KB |  |           lin.t · 11-18 09:21          |
|    ▸ DIR api/                 目录 |  | [e4f5a6b] feat(order): 支持部分退款     |
|    ▸ DIR repo/                目录 |  |           wang.y · 11-18 08:47         |
|    FILE config.yaml          620 B |  | …                                      |
| ▸ DIR tests/                  目录 |  | [上一页] 第 1 / 2 页 · 每页 6 条 [下一页] |
| ▸ DIR assets/                 目录 |  +--------------------------------------+
|   FILE README.md            4.2 KB |
|   FILE package.json         1.1 KB |
| [i] 目录树不完整，请逐级浏览（供应商分页）                                  |
| 演示：尝试读取 ../etc/passwd · 路径在请求前校验                             |
+------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 目录树行 | Tree row | 目录可逐级展开 / 收起；文件显示名称、类型、大小；缩进 20px/级 |
| 展开箭头 | Text caret | ▸ / ▾；键盘可聚焦，Enter / Space 展开 |
| 还有更多 | Link | 单个目录受供应商分页限制时出现「还有更多（n 条未加载）· 加载下一页」；加载后显示「已加载全部」 |
| 目录树不完整 | Warning note | 供应商标记 `truncated` 时显示「目录树不完整，请逐级浏览」，不当作完整结果 |
| 提交行 | Row | sha 短号（mono）、标题、作者、时间；按时间倒序 |
| 提交分页 | Pager | 「第 n / N 页 · 每页 6 条」；上一页 / 下一页；空态「没有提交」 |
| 文件点击 | Row action | 打开文件查看抽屉；已解绑时 `aria-disabled="true"` 且不发起请求 |
| 条目上限 | Notice | 不显示供应商原始响应；字段缺失按「未知」展示（实现约定） |

**States**：default / loading（目录树与提交骨架）/ success（实时结果）/ error（供应商失败 + 重试）/ empty（无提交 / 未同步 / 已解绑）。

### 文件查看抽屉（US-022）

**Purpose**：按 ref 按需预览单个 UTF-8 文本文件，拒绝超限、二进制与非法路径。

**Layout**：
```
+--------------------------------------------------+
| src/main.py                               [关闭] |
| ref main · 8.6 KB · 读取于 2026-11-18 10:52      |
+--------------------------------------------------+
| from api.client import CodeupClient              |
|                                                  |
| def main():                                      |
|     client = CodeupClient()                      |
|     ...                                          |
+--------------------------------------------------+
| 内容不写入会话制品与 AiCallRecord；若引用进分析，  |
| 按 200,000 字符上限计入。                        |
+--------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 抽屉 | Right drawer（480px） | 遮罩 + 右侧滑入；Esc 关闭；关闭后焦点回到触发文件行 |
| 路径 / ref / 大小 / 读取时间 | Header + mono | 展示路径、ref（分支 / commit）、大小与读取时间 |
| 内容 | `<pre>` mono | 只读、可滚动；UTF-8 文本按原样展示 |
| 关闭 | Icon button | 关闭抽屉；点击遮罩或按 Esc 同样关闭 |
| 底部提示 | Static text | 「不写会话制品与 AiCallRecord；引用进分析计入 200,000 字符」 |
| 超 1 MiB | Error state | 显示实际大小与上限 1 MiB（1,048,576 字节），提示改用更小范围或粘贴片段，不截断 |
| 二进制 / 非 UTF-8 | Error state | 「二进制 / 非文本文件不支持预览」，不展示乱码 |
| 非法路径 | Error state（请求前） | 路径含 `..` / 绝对路径 / 非法 ref 时前置拒绝，说明原因且不产生读取记录 |

**States**：default（打开中）/ loading（骨架）/ success（内容）/ error（超限 / 二进制 / 非 UTF-8 / 非法路径 / 网络失败）/ empty（文件为 0 字节时提示「文件为空」）。

### 令牌失效横幅与更新令牌（US-023）

**Purpose**：令牌失效时统一提示重填；重填并测试成功后恢复「已连接」，保留原绑定与元数据。

**Layout**：
```
项目上下文页顶部：
+--------------------------------------------------------------------------------+
| [!] 令牌失效或权限不足，请重新填写。同一绑定只提示一次，不重复弹错；仍可查看上次同步基线。 |
|                                        [重新填写令牌]  [查看基线快照]             |
+--------------------------------------------------------------------------------+

更新令牌表单：
+------------------------------------------------------------------+
| 更新访问令牌                                                [关闭] |
| [云效 Codeup] pay-group/pay-api     当前令牌 ****9c31            |
| 新访问令牌 [••••••••••]  hint: 保存后只显示掩码；留空表示不修改     |
| [测试连接]  [ConnectionTestBadge：成功 / 鉴权失败 / 网络失败 / 权限不足 / 已失效] |
|                                          [取消]  [保存令牌]       |
+------------------------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 失效横幅 | Banner（error） | 页面级唯一；聚合所有「令牌失效」绑定；提供「重新填写令牌」「查看基线快照」 |
| 绑定行徽标 | Status pill | 「令牌失效」；行内补充「可查看上次同步基线，重新填写并测试成功即恢复」 |
| 更新令牌 | Form（token 模式） | 提供商 / 仓库只读；令牌留空表示不修改；保存只替换令牌与掩码 |
| 测试后恢复 | State transition | 新令牌测试成功 → 保存后状态「已连接」；bindingId、元数据、历史记录不变 |
| 过期提示 | Badge | 供应商提供过期时间时展示；剩余 < 7 天显示「即将过期 · n 天」；无数据不推测 |
| 浏览页提示 | Banner（error / info） | 令牌失效时提示重填，并标明当前为上次同步基线 |

**States**：default（无失效）/ invalid（横幅 + 行徽标）/ updating（表单 + 测试中）/ recovered（成功横幅「已恢复连接」）/ empty（不适用）。

### 解绑确认对话框（US-023）

**Purpose**：在删除令牌前完整列出后果，二次确认。

**Layout**：
```
+--------------------------------------------------------------+
| 撤销仓库绑定？                                                |
| 将撤销 pay/checkout 的绑定与令牌。撤销后：                     |
|  • 加密令牌被删除，此后不再发起任何供应商请求；                 |
|  • 仓库 / 分支 / 提交快照保留并标「已解绑」，只读可查；           |
|  • 目录树与文件读取入口置灰、不可用；                          |
|  • 历史会话、制品与调用记录不变；                              |
|  • 重新绑定同一仓库会生成新的 bindingId 与新令牌。              |
|                                    [取消]  [确认解绑]          |
+--------------------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 标题 | Dialog title | 「撤销仓库绑定？」 |
| 后果列表 | List | 五条固定后果；不省略、不折叠 |
| 取消 | Secondary button | 关闭对话框，不做任何修改；焦点回到「解绑」按钮 |
| 确认解绑 | Danger button | 状态置「已解绑」、令牌掩码「—」、不再请求；快照只读；Toast / 横幅提示 |
| 焦点与 Esc | Keyboard | 打开时焦点落在「取消」；Esc 关闭；模态期间内容区不可交互 |

**States**：default / confirm-loading（确认按钮禁用）/ success（已解绑横幅）/ error（解绑失败，保留绑定并提示重试）/ empty（不适用）。

### 已解绑后的只读状态（US-023）

**Purpose**：解绑后仍可回看快照，但明确禁止同步与读文件。

**Layout**：
```
项目上下文页：
+-----------------------------------------------------------------------+
| GitHub pay/docs  已解绑   [已解绑：快照只读可查，目录树与文件读取不可用] |
| 默认分支 main · 令牌 — · 上次同步 2026-11-15 11:02 · 耗时 3.4s · 成功   |
| 基线 main @ c9d0e11 · 2026-11-15 11:02                                  |
| [查看快照] [重新绑定]                          [查看同步记录]            |
+-----------------------------------------------------------------------+

仓库浏览页：
+-----------------------------------------------------------------------+
| [i] 已解绑，目录树与文件读取不可用。快照只读；重新绑定会生成新 bindingId。 |
| 仓库 [pay/docs v]（禁用）  分支 [main v]（禁用）  [刷新]（禁用）         |
| 目录树行全部 aria-disabled；点击不发起请求                                |
+-----------------------------------------------------------------------+
```

**Key Elements**：

| Element | Type | Behavior |
|---------|------|----------|
| 已解绑行 | Grey card | 整行置灰；令牌「—」；状态徽标「已解绑」；不显示同步 / 更新令牌 / 解绑 |
| 查看快照 | Secondary button | 进入浏览页只读态：选择器与刷新禁用，目录树行不可点击 |
| 重新绑定 | Secondary button | 打开新增表单并预填提供商与仓库；保存生成新 bindingId 与新令牌 |
| 只读提示 | Banner（warning） | 「已解绑，目录树与文件读取不可用」；不写任何请求 |
| 历史不变 | Static text | 历史会话、制品与调用记录不改；已解绑绑定不参与 AI 调用 |

**States**：default（已解绑行）/ loading（快照加载骨架）/ success（只读快照可查）/ error（快照读取失败 + 重试）/ empty（无快照时「该绑定没有可查的快照」）。

### 键盘与可访问性（沿用 core 约定并补充）

- 所有按钮与树行可 Tab 聚焦，焦点环使用 `--color-ring`；目录树行用 `button` 元素，Enter / Space 展开或打开文件。
- 文件抽屉：打开后焦点进入抽屉，Esc 关闭并把焦点还给触发文件行；遮罩点击关闭。
- 解绑对话框：打开时焦点落在「取消」，Esc 关闭；模态期间背景内容不可聚焦。
- 图标按钮带 `aria-label`（关闭、打开导航、切换主题）；状态徽标用文本，不只靠颜色。
- 尊重 `prefers-reduced-motion`：抽屉与对话框的过渡关闭。
- 响应式：≤1180px 项目页与浏览页改为单列；≤768px 侧边栏转抽屉、文件抽屉 100% 宽、选择器单列；1440px 无横向滚动。

### 数据与令牌的界面边界

- 令牌字段始终 `type="password"`；列表 / 详情 / 测试结果只出现掩码（如 `ghp_****abcd`、`****9c31`），编辑时留空表示不修改。
- 任何错误文案不回显供应商原始响应或请求头；错误只给分类与可读原因。
- 文件内容只在抽屉中展示；抽屉底部固定说明「不写会话制品与 AiCallRecord；引用进分析计入 200,000 字符」。
- 同步记录只保存时间、耗时、结果分类与数量；不含令牌、响应原文与代码。

## 交互歧义假设（UXAMB）

### UXAMB-011

- 关联用户故事：US-017 / US-018 / US-019 / US-023
- 歧义描述：仓库绑定面板在项目上下文页内的落位与展开方式未定：与项目表单同页常显、同页折叠，还是独立页签。
- 设计建议：作为**项目详情表单下方的纵向区块**常显（≤1180px 时与项目列表、项目详情依次堆叠）；绑定列表与新增表单同区块，表单就地展开、不折叠。理由：core 已是「左项目列表 / 右项目详情」两栏，再横向切会变三栏；纵向区块承接表单里的「仓库地址」字段，符合 AMB-030 的单一事实来源。
- 状态：已确认
- 依据：answers.md 2026-11-18 11:12:30：「RX 全按建议」；UXAMB-011 按编排者修正采用「项目详情表单下方纵向区块」，用户接受。

### UXAMB-012

- 关联用户故事：US-020 / US-021 / US-022
- 歧义描述：仓库浏览（选择器、提交、目录树、读文件）是放在项目上下文页内展开，还是使用独立路由。

- 状态：已确认
- 依据：answers.md 2026-11-18 11:12:30：「RX 全按建议」
